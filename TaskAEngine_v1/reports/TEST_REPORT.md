## 合法 Batch 1 的训练与成本

仅对原始 Batch 1 的 445 行运行固定配方，没有新调参、没有使用 Batch 2 标签。两份新检查点保存在 [trained_candidates](trained_candidates)，父模型均为 stable，摘要与资源记录见 [benchmark.json](benchmark.json)。它们未经过新的独立质量验证，也未启用。

| 训练 | 计算 CPU 秒 | 计算经过秒 | 整个 API 经过秒 | 实际变化 |
| --- | ---: | ---: | ---: | --- |
| MLP 续训 5 epoch，lr=0.001 | 0.0781 | 0.1042 | 0.3885 | Adam 步数 160→180 |
| 固定瞬态融合重新拟合 | 0.0469 | 0.0536 | 0.2499 | 新中位数/IQR/岭回归状态 |

每个模型对 445 行输入预热一次、重复 50 次，均按批量调用；CPU 是进程累计时间，短调用受 Windows 计时粒度影响。

| 模型 | 计算 CPU 毫秒/批 | 计算经过毫秒/批 | API 经过毫秒/批 |
| --- | ---: | ---: | ---: |
| stable | 1.25 | 0.75 | 16.08 |
| fusion | 2.50 | 2.64 | 20.08 |
| witness_veto | 4.38 | 4.27 | 35.48 |
| raw_support | 8.75 | 8.31 | 63.36 |
| projected_support | 9.69 | 10.12 | 70.83 |

API 耗时含输入检查、指纹、SQLite、模型读取与哈希及输出列表构造，不含上游文件读取和 JSON 传输；本表使用内存特征。计算计时不含这些开销。每次 `predict` 为 1 次外层预测，融合/路由内部含多个分支；`evaluate` 为 2 次。部署时宜批量调用，不能把纯计算时间当作总 Harness 延迟。
