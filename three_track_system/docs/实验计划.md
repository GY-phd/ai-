# 实验计划（拿到官方数据后按此执行）

> 目的：用**规范的对照实验**支撑技术路线论证与主观分「实验规范与分析深度」。
> 每个实验都必须落 SwanLab（或本地镜像），命名与 tag 遵循统一体系。

## 0. 实验命名与 tag 体系

| 阶段 | name | tags |
|---|---|---|
| 基线 | `bootstrap/v0001_base_<model>` | `bootstrap, baseline, <model>` |
| 单轮重训 | `iteration_XXX/retrain_<model>` | `iteration, retrain, <drift_type>` |
| 消融 | `ablation/<模块>_off` | `ablation, <module>` |
| 超参 | `tuning/lr<x>_leaves<y>` | `tuning, sweep` |
| 运行级 | `run_summary` | `summary, final` |

`required_fields`（配置里已声明）：`config / metrics / tags / notes`。
`evo compliance` 会逐字段统计缺失，**提交前必须为 0**。

## 1. 必做的对照实验（主表）

在官方验证集 + 模拟漂移流上，固定随机种子（≥3 个种子取均值±std）：

| 编号 | 系统 | 说明 | 期望 |
|---|---|---|---|
| E0 | **冻结静态基线** | 只训练一次，永不更新 | 门槛③的对照底线 |
| E1 | 定时重训 | 固定每 N 窗口重训，无漂移检测 | 成本高、可能过度更新 |
| E2 | 仅漂移触发重训（无策略层） | 有监测+归因，超参固定 | 优于 E0/E1 |
| E3 | **完整系统（本方案）** | 模型层 + 策略层 bandit | 单位成本增益最优 |

关键指标（全部写入 `run_summary.json` 与实验记录）：

- `baseline_score` / `final_score` / `tail_score`（**流上在线口径**）
- `total_gpu_seconds` / `total_labels` / `total_tokens`
- `efficiency` = 增益 / 加权成本（对齐客观分）

> 判据：E3 的 `tail_score` 显著高于 E0，且 `efficiency` 高于 E1/E2。

## 2. 消融实验（证明每个模块有用）

| 编号 | 关闭的模块 | 观察点 |
|---|---|---|
| A1 | 漂移监测（改为每轮都更新） | 成本暴涨、无效更新比例 |
| A2 | 归因（只按 PSI 决定动作） | 概念漂移下错过更新 |
| A3 | 影子评估（候选直接上线） | 出现回退/性能抖动 |
| A4 | 策略层 bandit（参数固定） | efficiency 下降 |
| A5 | 新样本加权（等权重） | 适应速度变慢 |

记录"关闭某模块后 efficiency / tail_score 的变化"，这是答辩最有力的证据。

## 3. 阈值敏感性分析

对 `psi_trigger` ∈ {0.08, 0.1, 0.15, 0.2, 0.25} 做网格：

- 画 **更新次数 vs 尾段得分** 的权衡曲线
- 结论应指出"过低阈值 → 无效更新浪费预算；过高阈值 → 漏检导致退化"

## 4. 成本收益分析（客观分自评）

对每组实验计算：

```
效率 = (尾段得分 - 静态基线尾段得分) / (GPU秒 + 0.02×标注 + 0.0005×Token)
```

用一张图（横轴成本、纵轴增益）把所有方案画上去，直观展示帕累托前沿。

## 5. 鲁棒性实验

| 场景 | 配置 | 验证点 |
|---|---|---|
| 标签延迟 | `label_delay=500` | 系统不崩、性能下降可接受 |
| 预算紧张 | `max_label_quota=500` | 自动转向复用历史标注 |
| LLM 不可用 | 不设 `PYTRIO_*` | 规则降级仍能跑完 |
| 极端漂移 | `drift_strength=0.6` | 回滚机制被触发且有效 |
