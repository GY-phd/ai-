# 系统运行说明

> **本文档描述的是仓库里的研究运行时（`evo` / `tracks` / `harness`）。**
>
> **比赛平台的正式入口不是这些。** 平台通过 `contest_harness` SDK 的固定
> 入口调用参赛代码，镜像里的入口只有一个：
>
> ```bash
> python3 /app/harness.py describe
> python3 /app/harness.py train
> python3 /app/harness.py predict
> ```
>
> 这个入口落到 `/app/contest_submission.py`，再落到 `contest_baselines/`。
> `python -m evo serve` / `python -m evo predict` 是**早期单任务实现**的
> 离线协议工具，**不在提交镜像里**，也不是平台的调用方式。
> 详见 [`HARNESS_INTEGRATION_RECORD.md`](HARNESS_INTEGRATION_RECORD.md)。

## 1. 运行环境

| 项 | 要求 |
|---|---|
| Python | ≥ 3.10（开发用 3.12） |
| 硬件 | **四核八G，无 GPU**（赛题评测环境）。树模型秒级训练 |
| 线程 | `runtime.n_jobs: 4` —— 必须限制，否则 LightGBM/随机森林吃满全部核 |
| 网络 | **不需要**。离线可完整运行；LLM 走 PyArrow（平台注入环境变量） |
| 系统依赖 | 无（纯 Python） |

Python 依赖见 `pyproject.toml`：numpy / pandas / scikit-learn / scipy / lightgbm / pyyaml / joblib / swanlab。

## 2. 安装

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv -e ".[dev]"
# 可选: 需要大模型决策时
uv pip install --python .venv -e ".[llm]"
```

## 3. 命令一览

| 命令 | 作用 | 退出码 |
|---|---|---|
| `python -m evo doctor` | 环境自检（依赖/数据/LLM/**赛题合规**） | 0 正常 / 2 有违规 |
| `python -m evo run` | 运行完整自进化闭环（**研究运行时**，非平台入口） | 0 成功 |
| `python -m evo run-batches` | **批次下发模式**（赛题 B 包协议） | 0 成功 |
| `python -m evo serve` | 早期协议的预测服务（**离线工具**，不在提交镜像内） | 0 |
| `python -m evo predict` | 离线批量预测（校验输出格式，**非平台入口**） | 0 成功 / 2 有错误行 |
| `python -m evo report` | 打印运行汇总、**成本收益**、假设循环 | 0 |
| `python -m evo gates` | **基础运行门槛自检**（≥3 次迭代 + 不低于静态基线） | 0 通过 / 2 未通过 |
| `python -m evo verify-audit` | 校验审计哈希链完整性 | 0 完整 / 2 断裂 |
| `python -m evo compliance` | 实验记录规范合规自检 | 0 合规 / 2 不合规 |
| `python scripts/build_submission.py` | **构建提交包**（自动排除模型权重） | 0 成功 / 2 超限 |

所有子命令均支持 `--set key=value` 覆盖配置，例如
`python -m evo report --set paths.artifacts_root=artifacts/official`。

（Windows 下把 `python` 换成 `.\.venv\Scripts\python`，并设 `$env:PYTHONPATH="src"`）

## 3.1 早期协议（`serve` / `predict`，离线工具）

> ⚠️ **这一节描述的 `evo` 协议是早期单任务实现，平台不使用它。**
> 平台的正式协议由 `contest_harness` SDK 实现，入口是
> `python3 /app/harness.py predict`，代码在 `contest_baselines/predict.py`。
> 下面保留本节是为了让本仓库的研究脚本仍可离线自检输出格式。

协议来源：赛题包 `baselines/predict.py` 与 `baselines/data.py`。

请求（stdin 逐行 JSON）：

```json
{"task": "regression", "inputs": {"features": {"horizontal": [1.0], "vertical": [2.0]}}}
```

响应（stdout 逐行 JSON）：

```json
{"outputs": {"value": 424.2}}                                  // 回归, 非负
{"outputs": [{"label": "Ethanol", "score": 0.87}, ...]}        // 分类
```

```bash
# 离线自检服务（研究用；平台不调用它）
python -m evo serve --config /app/configs/default.yaml

# 离线校验输出格式（研究用；平台不调用它）
python -m evo predict --input req.jsonl --output pred.jsonl
```

关键约束（均已实现并有测试覆盖）：

- 请求只能含 `task` / `inputs`，多余键报错；`task` 不匹配报错
- **特征 schema 必须与检查点一致**（逐条比对官方 `flatten` 的字段路径），
  不一致直接报错 —— 特征错位是最难查的 bug，模型照常出数但全错
- RUL 预测**截断至非负值**
- JSON 不允许 NaN/Inf
- 单条脏数据**不终止服务**，写错误行后继续

## 4. 镜像内的启动方式

> **提交镜像的入口是 SDK 的固定入口，平台自己拉起，不需要手工启动：**
>
> ```bash
> python3 /app/harness.py describe   # 声明协议与任务
> python3 /app/harness.py train      # 一轮续训（含一次真实模型调用）
> python3 /app/harness.py predict    # 逐行应答隐藏样本
> ```
>
> 下面第 4 节描述的是**研究运行时**在本地镜像里的启动方式，与平台无关。

镜像启动后应执行：

```bash
export PYTHONPATH=/app/src          # 或 pip install -e .
python -m evo run --config /app/configs/default.yaml
```

关键：**不需要任何人工输入**。系统全程自动完成：
漂移监测 → 归因 → 决策 → 训练 → 影子评估 → 上线/拒绝 → 回滚检查 → 汇总输出。

### 4.1 批次下发模式（赛题 B 包）

赛题协议：**必须先输出当前批次模型或"不上线"的判断，才能获取下一批数据**。

```bash
# 方式一: 评测平台把批次文件落到共享目录
python -m evo run-batches --batch-dir /app/data/batches

# 方式二: 评测方通过 stdin 逐批投递 JSON {"X": [[...]], "y": [...]}
python -m evo run-batches --fetch-stdin

# 方式三: 本地联调（合成流切批）
python -m evo run-batches --synthetic --max-batches 8
```

每批的应答写入 `artifacts/batch_responses.jsonl`，内容为：

```json
{
  "batch_id": 4,
  "n_samples": 800,
  "predictions": [0.1, 0.9, "..."],
  "decision": {"action": "retrain", "approved": true, "version": "v0003_iter004_lgbm"},
  "model_version": "v0003_iter004_lgbm",
  "approved": true,
  "gain": 0.1357,
  "metrics": {"score": 0.671, "baseline_score": 0.594}
}
```

> 赛题明确「评测时总能拿到标签，且无需消耗配额申请」，因此批次模式下
> `data.batched_free_labels: true` 会跳过标注采购流程。

### 输出物（评测方读取）

| 文件 | 内容 |
|---|---|
| `artifacts/run_summary.json` | 运行汇总 + 逐轮明细 + **门槛自检**（主结果） |
| `artifacts/online_curve.json` | 逐窗口性能曲线（自适应 vs 静态基线） |
| `artifacts/hypothesis_cycles.jsonl` | **假设-实验-决策**四段式证据链（赛题门槛②③） |
| `artifacts/batch_responses.jsonl` | 批次模式下的逐批应答 |
| `artifacts/experiments/experiments.jsonl` | 全部实验记录（《实验记录规范》镜像） |
| `artifacts/audit/audit.jsonl` | 哈希链审计日志 |
| `artifacts/models/*.pkl` | 所有模型版本（可回滚）——**不得打进提交包** |

## 4.2 赛题 profile 与评分口径

指标口径**严格对齐官方 `baselines/docs/{A,B,C}.md`**，通过 `data.profile` 选择：

| profile | 任务 | 主指标 | 辅助指标 | 官方明确不使用 |
|---|---|---|---|---|
| `A` | 气体 6 类分类 | **Macro-F1**（越高越好） | Accuracy、混淆矩阵 | 不把连续数值当标签 |
| `B` | 轴承 RUL 回归 | **RMSE**（越低越好） | MAE | **不使用严重退化分类/漏报率**、65%/20% 阈值、寿命比例标签 |
| `C` | 发动机 RUL 回归 | **RMSE**（越低越好） | MAE、**NASA 非对称分数** | 不做健康/预警/危险分箱、目标不封顶 |
| `auto` | — | 按 `data.task` 推断（回归→C，分类→A） | | |

```yaml
data:
  task: "regression"   # binary | regression
  profile: "B"         # A | B | C | auto
```

> ⚠️ **为什么 B 包不能用漏报率打分**：官方原文「不以严重故障漏报率评价本任务」。
> 若把漏报率并入 score，系统会去优化一个**不被评分**的量，反而损害真正的
> 主指标 RMSE —— 这是典型的「优化了错误目标」。因此漏报率仅作为
> **可选诊断指标**（`metrics.severe_threshold` / `metrics.severe_classes`）输出，
> **不进 score、不否决上线**。

> ⚠️ **C 包的 NASA 非对称分数用官方公式**：逐样本惩罚之**和**，
> 高估剩余寿命的惩罚是低估的 **5 倍**。官方特别说明「该分数是逐样本惩罚之和，
> 样本数量或测试协议不同的结果不能直接横比」—— 因此不能取均值冒充。

## 4.3 假设-实验-决策四段式留痕（赛题门槛②③）

赛题门槛③要求「至少 3 次『读历史→提假设→做实验→做决策』」。
仅有指标曲线不足以证明系统是**自主迭代**而非随机试参，因此每轮迭代都留下
四段式、可证伪的证据链（`artifacts/hypothesis_cycles.jsonl`）：

| 段 | 内容 |
|---|---|
| 读历史 | 漂移指标（PSI/severity）、归因类型与关键特征、基线误差、近几轮对比、当前 champion 策略 |
| 提假设 | 一句**可证伪**的假设 + 预期增益 + **证伪条件**（什么情况下判定假设不成立） |
| 做实验 | 候选数、影子评估样本量、p 值、基线分/候选分/增益、算力/标注/token 成本 |
| 做决策 | 上线或拒绝、理由、模型版本、是否回滚、决策来源（策略 / LLM / 门槛探针） |

门槛自检会额外统计 `hypothesis_cycles` 与
`hypothesis_cycles_with_falsification`，不足 3 次即判定未通过。

## 4.3.1 View 层（只读查询 API）的部署形态

View 层是**进程内只读库**，**不随镜像自动启动 HTTP 服务**。

| 项 | 说明 |
|---|---|
| 是什么 | 对 Model 层表的一组命名只读查询，返回可直接序列化为 JSON 的字典 |
| 部署形态 | **进程内**调用。镜像入口**不**派生常驻进程、守护线程或后台服务来提供 View 查询 |
| 为什么 | 镜像入口必须是**唯一**入口且轮次结束即退出。一个活过轮次的服务会让"跑完了没有"变得不确定 |
| 端点 | `overview` / `ledger` / `rounds` / `metrics` / `champion` / `hypothesis` / `predict` |
| 可选 HTTP | `layers/view/server.py` 是同一批查询的**可选** HTTP 包装，供看板或评审页面使用。**镜像内不启动** |

在镜像内使用它的方式只有一种——**在进程内直接调用**：

```python
from contest_baselines.layers.view import View

view = View("/workspace/state")
print(view.to_json(view.overview()))     # 概览
print(view.to_json(view.hypothesis()))   # 每个假设的结论
```

每个答案都带 `kind` 与 `version` 字段，消费方无需猜测拿到的是什么：

```json
{"kind": "overview", "version": 1, "rounds": 10, "best": {"metric": "macro_f1", "value": 0.7192}}
```

View **只读**：全部查询都是对表的纯读取，不写文件、不改状态，因此指向一份冻结归档目录时，与指向活动目录给出的答案完全一致。

## 4.4 成本收益报告（客观分「资源效率」+ 专家评审「成本收益」）
`run_summary.json` 的 `cost_benefit` 字段逐维度给出单位成本收益：

| 指标 | 含义 |
|---|---|
| `tail_gain` | 尾段相对静态基线的增益（长期价值） |
| `gain_per_gpu_second` | 每单位算力的增益 |
| `gain_per_label` | 每单位标注配额的增益（标注是最稀缺资源） |
| `gain_per_1k_tokens` | 每千 token 的增益（LLM 驱动成本） |
| `trigger_approval_rate` | 触发更新的命中率（低 = 阈值过低，在浪费算力） |
| `resources` | 算力/标注/token/迭代/训练/上线数明细 |

## 5. 配置项说明（评测关注点）

```yaml
runtime:
  window_size: 500      # 漂移监测窗口; 必须 ≥ drift.min_samples_for_action
  window_step: null     # null = window_size//2 (滑窗)
  label_delay: 0        # 标签滞后步数
  offline: true         # 禁止外联 (安全要求)
  n_jobs: 4             # 线程数上限 (评测环境仅 4 核)

data:
  task: "binary"             # binary | regression | multiclass
  profile: "auto"            # A | B | C | auto —— 决定评分指标口径 (见 4.2)
  batched: false            # 批次下发模式开关
  batch_size: 500           # 单批样本数
  batched_free_labels: true # B 包: 标签总是可得且不消耗配额

metrics:
  # 严重退化漏报 (仅诊断, **不进 score、不否决上线**)
  # 官方 B 包明确"不以严重故障漏报率评价本任务"
  severe_classes: null
  severe_threshold: null
  asym_error_cap: null      # 非对称评分的误差截断

budget:                 # 受控 RSI 的硬约束
  max_gpu_seconds: 3600
  max_label_quota: 2000
  max_llm_tokens: 200000
  per_iteration_label_quota: 500
  halt_ratio: 0.9

safety:
  max_consecutive_failures: 3   # 连续失败熔断
  rollback_margin: 0.005        # 上线增益门限
  shadow_min_steps: 300         # 影子评估最少样本
  alpha: 0.05                   # McNemar 显著性水平
  max_iterations: 50

gates:
  min_iterations: 3      # 赛题: 至少三次尝试迭代

experiment:
  swanlab_public: true   # 赛题: Swan Lab 记录必须公开

llm:
  allowed_models:        # 赛题: 仅允许千问 27B / 4B
    - "Qwen3.8-27B"
    - "Qwen3.5-4B"
```

## 6. 大模型接入

```bash
export PYTRIO_BASE_URL="http://<endpoint>/v1"
export PYTRIO_API_KEY="<key>"
export PYTRIO_MODEL="Qwen3.8-27B"     # 或 Qwen3.5-4B
```

- 有服务：LLM 参与"是否更新 + 更新方式"的决策，Token 计入成本
- 无服务：自动降级为**确定性规则**，闭环照常运行，Token 成本为 0
- **模型白名单**：不在 `llm.allowed_models` 内的模型**不会真正发起调用**，
  避免误配外部模型导致违规

> 降级是刻意的安全设计：评测环境若服务不可用，系统不得因此失败。

### 6.1 路线二：PyTRiO 后训练驱动模型

赛题给出两条路线，**两者都支持**：

| 路线 | 说明 | 配置 |
|---|---|---|
| 路线一 | 指定基模（Qwen3.8-27B / Qwen3.5-4B）直接作为 Harness 驱动模型 | `PYTRIO_MODEL=Qwen3.8-27B` |
| 路线二 | 以千问为**基座**，经 PyTRiO 后训练获得驱动模型 | `PYTRIO_MODEL=<后训练模型名>` |

路线二的后训练模型名通常带后缀（如 `qwen3.8-27b-ft-20261115`）。
白名单校验分三层，**不会把合规的后训练模型误判为违规**：

1. **显式豁免**：命中 `llm.derived_models` → 放行
2. **基座合规**：归一化后模型名**包含**白名单基座 → 放行
3. 否则拒绝，且**不发起调用**

```yaml
llm:
  allowed_models:      # 白名单基座
    - "Qwen3.8-27B"
    - "Qwen3.5-4B"
  derived_models: []   # 仅当平台完全改写后训练模型命名时才需声明
```

## 7. 可观测性

每轮迭代产出（`run_summary.json` 的 `records`）：

```json
{
  "index": 8,
  "window": [3500, 4000],
  "drift": {"max_psi": 0.23, "severity": "alarm", "top_features": [["f3", 0.23]]},
  "attribution": {"drift_type": "concept", "culprit_features": ["f3"], "rationale": "..."},
  "decision": {"action": "retrain", "target_model": "lgbm", "source": "rules_fallback"},
  "approved": true, "version": "v0009_iter008_lgbm",
  "gain": 0.0929, "cost_gpu_seconds": 0.2, "cost_labels": 500, "cost_tokens": 0
}
```

这使每一轮"为什么更新/为什么不更新"都可追溯，直接对应主观分中的
「实验规范与分析深度」「安全可控与工业落地」。

## 8. 故障处理

| 现象 | 处理 |
|---|---|
| 运行中断 | 审计日志可定位最后事件；已注册模型可继续用 |
| 连续更新失败 | `max_consecutive_failures` 触发熔断，系统转为只监控模式 |
| 模型退化 | 决策层发 `rollback`，回退到上一个通过评估版本 |
| 预算耗尽 | 停止主动更新（GPU/Token 耗尽），或仅复用历史标注（标注配额耗尽） |

## 9. 提交前检查清单

```bash
python -m evo doctor                      # 1. 合规体检 (无 violations)
python -m evo gates                       # 2. 基础门槛 (≥3 次迭代 + ≥ 静态基线)
python -m evo verify-audit                # 3. 审计链完整
python -m evo compliance                  # 4. 实验记录规范
python scripts/build_submission.py --out dist/submission   # 5. 打包 (自动排除权重)
```

第 5 步会产出 `submission_manifest.json`，列出每个文件的 SHA-256、体积，
并确认**权重文件数为 0**、总大小 < 2G。
