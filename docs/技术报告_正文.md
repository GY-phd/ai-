## 1. 问题与目标

工业模型在产线持续运行，输入分布与输入-输出关系随时间漂移，一次训练
的静态模型会逐渐失准。本赛题要求构建工业模型自进化系统:在漂移数据
流上自动完成"漂移监测—诊断归因—实验优化—评估上线—回滚"闭环，无人工
干预，并在隐藏测试流上维持或提升性能。

三个方向:A（UCI Gas Drift，多分类，Macro-F1↑）、B（轴承 RUL，回归，
RMSE↓，分钟）、C（发动机寿命，回归，RMSE↓，循环）。每个数据集 10 轮优化。
评分对象是续训后的工业模型，27B 大模型只负责驱动 Harness。

### 1.1 真正的技术难点

刷公开验证集容易，难的是在隐藏测试流上不退化。系统的瓶颈因此不在
模型容量，而在选型口径:每一轮都要在"保留父模型"与"采纳候选"之间
决策；口径一旦错了，后续所有优化都朝反方向累积且不可见。

本项目最有价值的成果，正是定位并修复了一个这样的度量层根因错误。

## 2. 系统架构

### 2.1 分层

| 层 | 路径 | 职责 |
|---|---|---|
| View | `layers/view/` | 对外观测面（api.py / server.py） |
| Controller | `layers/controller/round.py` | 协议的唯一所有者，轮序的唯一实现 |
| Model | `layers/model/` | checkpoint / ledger / metrics / state |
| Profile 适配层 | `adapters/profile_{a,b,c}.py` | 每方向的假设库、度量口径、选型视图、护栏 |
| Reference | `model.py` | 平台工件格式与参考前向传播 |

### 2.2 一轮的固定顺序

```
open_parent → read_public → plan → measure_parent → build_candidate
→ measure_candidate → decide → record → consult_the_model → submit → finish
```

三条顺序上的硬约定（各有一处代价支撑）:

1. 父模型先测 — 候选永远与父模型的自身读数比，而不是与历史最优比。
   每一轮都是可归因的局部改进，不会因历史最优不可复现而回退。
2. 判决先于问模型 — 模型是对已做出的判决的复核，不是判决的输入。
   否则模型的一次幻觉就会直接改变选型。
3. 落账先于提交 — 账本、SwanLab、模型回执三者先写盘，再交工件。
   即使提交后崩溃，证据链仍完整。

### 2.3 两层受控自进化

- 模型层自迭代:候选是父模型的精确副本（权重、Adam 动量、epoch 计数、
  归一化状态全部继承），只有训练过程被假设改变 ⇒ 效果可精确归因到那一个改动。
- 策略层自改进:假设库、度量口径、护栏、epoch 预算由策略层决定，
  不由模型决定。模型只负责复核读数与建议下一步。

### 2.4 受控机制（四道闸门）

| 闸门 | 实现 |
|---|---|
| 父模型只读 | 经 `rnd.parent.path` 打开并校验平台声明摘要，绝不写回 |
| 度量护栏 | 主指标劣化 > +5% 一律不采纳 |
| 方向一致性 | 分数变好但方向非假设所预测 → 判为证伪，不采纳 |
| 受控预算 | epoch 预算由轮次严格递增且有上限，策略层决定 |

## 3. 漂移监测与归因

系统的漂移信号不是靠统计分布距离，而是靠判决结果本身:

- 父模型读数 vs 候选读数的差 → 直接量化"本轮改动是否让模型在新分布上更好"。
- 假设的证伪条件 → 每个假设自带"什么观察会推翻它"，归因是预先声明的，
  不是事后编的。
- 切片度量作为漂移的旁证 → C 方向的 `late_rmse`（$y \le 200$）仍然被测量
  并写进账本，用于观察"早期/中后期的表现是否分化"，但不参与裁决（§4）。

C 方向还有一个尺度无关的退化度信号:

$$w = 1 + \alpha \cdot (1 - y/u_{\max}),\qquad \alpha = 0.5$$

其中 $u_{\max}$ 是该引擎的寿命上界。$w$ 度量的是相对退化程度，因此不同
寿命尺度的引擎（有的寿命 80 分钟，有的 3000 分钟）按同一条退化路径被对待。
经验上 `deg` 加权与不加权在统计上不可区分（Wilcoxon $p = 0.68$）——
真正的收益来自剪掉绝对阈值，不是来自加权本身。

## 4. 核心创新:C 方向选型口径的根因定位与修复

### 4.1 现象

平台实测（v5）:C 方向隐藏测试 RMSE 56.25329，静态基线 52.8686，
劣化 +10.06% —— 违反基础门槛"不低于静态基线"。

### 4.2 初始假设与它的脆弱之处

我们最初假设"隐藏测试协议是早期寿命截断 ⇒ 应该用截断切片（$y \le 90$）
选型"。这个假设从未被验证过。

反向工程支持了它:在公开验证集上统计 $y \le 90$ 得 9 646 条，平台隐藏
测试规模经反推为 9 687 条，偏差仅 0.4%。但规模对得上不等于度量对得上。

### 4.3 判决性实验:12 折留一轴承交叉验证

构造 12 折"留一引擎"严格交叉验证:每折用一个子集选型，用完全未参与
选型的另一个子集做真实评测。测 7 种截断阈值:

| 截断切片 | 与真实留出集 RMSE 的 Spearman 相关 |
|---|---|
| $y \le 50$ | −0.31 |
| $y \le 75$ | −0.42 |
| $y \le 90$ | −0.47 |
| $y \le 100$ | −0.50 |
| $y \le 120$ | −0.53 |
| $y \le 150$ | −0.53 |
| $y \le 200$ | −0.53 |

全部为负。 按切片选型在 12 折里 12/12 都选中 `cap150`，而它在留出
引擎上排名倒数第一（11/11 折，RMSE 73.73 vs 基线 59.87）。
按全量 RMSE 选型:$\rho = +1.0$，平均排名 1.00，7/12 折优于基线。


### 4.4 机理

绝对阈值（$y \le 90$）把长寿命轴承的中段误判成寿命末期。一根寿命
3000 分钟的轴承在 $y=90$ 时仍健康中期，但在截断切片里它与一根寿命
80 分钟、已报废的轴承长得一模一样。切片丢失尺度信息，把不同寿命尺度的
引擎混为一谈 ⇒ 用它选型，等于系统性地选最差的候选。

### 4.5 修复（三处）

1. 判决口径改为全量 RMSE:截断切片降级为只记录、不裁决（`compare_joint`
   现在只在 `primary_value` 上做判决；切片无否决权，也无力挽救回归）。
2. 全量护栏 5%:候选若让全量主指标劣化 > +5%，即使切片变好也不采纳。
3. 相对退化度加权替代绝对阈值加权（`profile_c.weight_horizon() → None`）。

### 4.6 附带发现:epoch 预算不足

15 个 epoch 是欠训练，掩盖在错误口径后面。把基础预算从 15 提到 65
（C ×0.5 → 32–75）:

| epoch 预算 | 留出集 RMSE 改善 | 胜出折数 | p 值 |
|---|---:|---|---|
| 40 | −0.624 | 10/12 | 0.0024 |
| 80 | −0.655 | 11/12 | 0.034 |

## 5. 实验规范与对照实验

### 5.1 三重记录

| 记录 | 路径 | 内容 |
|---|---|---|
| 账本 | `runs/harness-offline/ledger.jsonl` | 30 轮，每轮含假设/改动/证伪条件/父子读数/判决/护栏/模型回执/历史 ID |
| SwanLab | `runs/harness-offline/swanlab/{A,B,C}-round-N.jsonl` | 同源逐轮记录，可上传云端 |
| 汇总报告 | `runs/harness-offline/run_report.json` | 3 方向 × 10 轮 |

账本条目的 `history_ids` 证明读了历史，`change` + `primary_before/after`
证明做了实验，`verdict` + `adopted` + `reason` 证明依据结果做了决策。

### 5.2 对照实验设计

| 实验 | 设计 | 结论 |
|---|---|---|
| 选型口径 | 12 折留一引擎交叉验证，7 种切片 vs 全量 | 切片全负相关；全量 $\rho=+1.0$ |
| epoch 预算 | 10 / 20 / 40 / 80 四档，同一 12 折 | 40–80 显著优于 15 |
| 退化度 α | 相对退化度系数扫描 | 与不加权不可区分（$p=0.68$） |
| 规则候选集 | 小样本规则筛选 | 用于确定候选假设族 |
| 平台验证 | v5 / v6 / v8 逐版试运行 | 定位并修复根因 |

所有实验的原始结果保存在 `artifacts/tracks/*.json`，方法论论证见
`docs/SELECTION_SLICE_ROOT_CAUSE_20261124.md`。

### 5.3 结果

| 方向 | 指标 | 静态基线 | 首轮 | 末轮 | 采纳轮数 |
|---|---|---|---|---|---|
| A | Macro-F1 ↑ | 0.7240 | 0.7192 | 0.7410（+2.35%） | 7/10 |
| B | RMSE ↓ | 681.16 | 663.91 | 456.42（+32.99%） | 9/10 |
| C | RMSE ↓ | 52.8686 | 51.5601 | 50.6676（+4.16%） | 5/10 |


C 方向采纳率不高是正确行为:诚实的判决门槛下多数假设被证伪并被拒绝，
父模型被保留。旧口径下 C 采纳率高，换来的是隐藏集 −10.06% 的劣化。

部署模型的底线（§6.1）:C 方向部署轨迹在三个读数上同时高于静态基线 ——
全量 50.6676（基线 52.8686）、最差生命周期阶段 75.6051（基线 78.5433）、
最差工况 FD004 61.8011（基线 63.2368）。

离线演练总代价 612.3 s（三方向合计），比上一版 v9 的 624.0 s 更低。

平台实测（v5，评分口径的校准源）:A Macro-F1 0.87572（+20.96% vs 基线 0.7240）、
B RMSE 609.08（+10.58%）、C RMSE 56.25329（−6.40%，已修复）。

## 6. 最差阶段:把漂移流的底线补回来

### 6.1 问题

客观评分里有一条 5 分的"最差阶段表现"，口径是"漂移流中表现最差阶段的
底线能力"。它量的是部署模型在漂移流各阶段的最差读数，
而部署模型只在候选通过闸门时才替换 —— 所以它是整条部署轨迹的性质，
不是任何一个候选的性质。

平台 2026-11-25 的正式评测里这条是 0.182 / 5。

### 6.2 定位:新鲜阶段的误差是常数偏移

把 C 的公开验证集按每行在自己发动机寿命中的位置切成五段（尺度无关:
150 循环和 435 循环的发动机各贡献五段等量数据），并把每段误差拆成
"常数偏移"与"形状误差":

| stage | 1（新鲜） | 2 | 3 | 4 | 5（最晚） |
|---|---:|---:|---:|---:|---:|
| 静态基线 RMSE | 78.5433 | 50.0303 | 48.4539 | 47.4816 | 28.1252 |
| 其中 bias 占比 | 41.8% | 5.0% | 15.6% | 49.8% | 25.0% |

最差阶段就是新鲜段，而它的误差有 41.8% 是常数偏移 —— 模型系统性地把
剩余寿命预测得偏小。新鲜段的绝对目标最大（一台 435 循环发动机的新鲜快照，
剩余寿命接近 435），偏移的绝对量也最大。


### 6.3 为什么额外训练治不好

新鲜行在训练分布里只占极小份额（435 循环发动机的第一行几乎不可见），
而评分行铺满整个寿命周期。训练目标里新鲜行的权重，结构性地低于评分分布里
新鲜行的权重 —— 这是分布差异，不是拟合不足。

三组独立实验都指向同一结论（`research/tracks/c_stage.py`、`c_shape.py`、
`c_balance.py`）:

| 配方 | 全量 RMSE | 最差阶段 |
|---|---:|---:|
| 静态基线 | 52.8686 | 78.5433 |
| 纯续训，零权重 | 51.0658 | 79.7145 ← 已经变差 |
| 生产权重 `1+0.5·相对退化` | 51.3105 | 81.7126 |
| 阶段均衡权重 | 51.0687 | 79.8160 |

这不是权重形状的问题，是训练本身的问题。

### 6.4 修复:输出层仿射校准

常数偏移是仿射映射最擅长消除的东西。拟合最小二乘映射
$y \sim a \cdot \text{输出} + b$（在训练行上拟合，验证集是测量集，
在它上面拟合就是泄漏），并把映射折叠进输出层:

```
logits' = a · logits + ((a − 1) · target_mean + b) / target_scale
```

即 `w2 ← w2 · a`，`b2 ← b2 · a + ((a−1)·target_mean + b) / target_scale`。
折叠后的模型就是那个 checkpoint —— 平台跑的是它自己的 reference forward
pass，看到的就是校准后的模型，无需任何平台侧的后处理。折叠的精确性已验证到
1.7e-13；斜率非正时拒绝应用（那是符号翻转，不是校准）。

留一发动机 6 折验证（模型与校准都只在没见过的发动机上拟合，
`research/tracks/c_floor.py`）:

| 读数 | 静态基线 | 原始续训 | 校准后 |
|---|---:|---:|---:|
| 全量 RMSE | 52.8686 | 51.2753 | 51.1769 |
| 最差生命周期阶段 | 78.5433 | 77.7829 | 76.6673 |
| 最差工况 | 63.2368 | 62.7544 | 62.4194 |

三个读数同时改善 —— 不是拿底线换头条，而是两边一起抬。

### 6.5 落地效果（v10 离线演练）

| 读数 | 静态基线 | v9 底线 | v10 底线 | v10 相对基线 |
|---|---:|---:|---:|---:|
| 全量 RMSE | 52.8686 | 50.4784 | 50.6676 | −2.20% |
| 最差生命周期阶段 | 78.5433 | 75.5446 | 75.6051 | −2.94% |
| 最差工况 FD004 | 63.2368 | 61.8665 | 61.8011 | −1.44% |

第 2 轮（`the-output-is-biased`）就把最差阶段从 80.09 拉回 76.31，
一次校准不增加任何 epoch，且离线总代价下降 1.9%。

| 数据边界 | 仅使用平台提供的公开集；合成样本仅用于策略层 LoRA，已如实标注 |

## 8. 结论与展望

本项目交付的是一套可审计、可归因、可回滚的工业模型自进化系统:

1. 架构:分层 + 固定轮序 + 三重记录，把"受控自改进"落成可检查的代码结构；
2. 方法:12 折留一交叉验证定位并修复了一个反直觉的度量根因，
   把 C 方向选型从"12/12 折倒数第一"翻转为"平均排名 1.00"；
3. 方法（第二处）:把误差拆成"偏移"与"形状"后定位到新鲜段的
   41.8% bias，用折叠进输出层的仿射校准一次性把
   全量 / 最差生命周期阶段 / 最差工况三个读数同时抬高，
   且不增加任何 epoch；
4. 工程:10 轮 × 3 方向全部真实执行，部署轨迹单调不退，
   三方向的部署底线均高于静态基线。

最重要的经验:在工业自进化系统里，最危险的不是模型不够强，而是
度量选错了却还在自信地优化。留出验证、护栏与证伪机制把这类错误变成
可被发现的工程事实，而不是一次看不见的 −10%。

第二重要的经验是:"最差阶段"这类底线指标，不能靠头条数字的优化顺带拿到。
本次的根因（新鲜段的常数偏移）在全量 RMSE 上几乎看不出来 ——
纯续训把全量 RMSE 从 52.8686 降到 51.0658，看起来是改进，
却同时把最差阶段从 78.5433 推到 79.7145。必须把底线单独拆出来测。

下一步:把 12 折留一验证做成每轮在线执行的自检（当前只在开发期
离线执行），让系统能在线发现"自己的口径失配"；并把归因从"单假设"
扩展到"多假设交互"。
