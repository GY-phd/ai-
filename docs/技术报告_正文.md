# 智训引擎 — 技术报告

**赛题**：“智训引擎”——工业制造场景下的模型训练与超参数优化
**队伍**：gy_65511　**版本**：v8　**篇幅**：8 页（平台上限 10 页）

---

## 1. 问题与目标

工业模型在产线持续运行，输入分布与输入-输出关系随时间漂移，一次训练
的静态模型会逐渐失准。本赛题要求构建**工业模型自进化系统**：在漂移数据
流上自动完成「漂移监测—诊断归因—实验优化—评估上线—回滚」闭环，无人工
干预，并在隐藏测试流上维持或提升性能。

三个方向：A（UCI Gas Drift，多分类，Macro-F1↑）、B（轴承 RUL，回归，
RMSE↓，分钟）、C（发动机寿命，回归，RMSE↓，循环）。每个数据集 10 轮优化。
**评分对象是续训后的工业模型**，27B 大模型只负责驱动 Harness。

### 1.1 真正的技术难点

刷公开验证集容易，难的是**在隐藏测试流上不退化**。系统的瓶颈因此不在
模型容量，而在**选型口径**：每一轮都要在「保留父模型」与「采纳候选」之间
决策；口径一旦错了，后续所有优化都朝反方向累积且**不可见**。

本项目最有价值的成果，正是定位并修复了一个这样的**度量层根因错误**。

## 2. 系统架构

### 2.1 分层

| 层 | 路径 | 职责 |
|---|---|---|
| View | `layers/view/` | 对外观测面（api.py / server.py） |
| Controller | `layers/controller/round.py` | **协议的唯一所有者**，轮序的唯一实现 |
| Model | `layers/model/` | checkpoint / ledger / metrics / state |
| Profile 适配层 | `adapters/profile_{a,b,c}.py` | 每方向的假设库、度量口径、选型视图、护栏 |
| Reference | `model.py` | 平台工件格式与参考前向传播 |

### 2.2 一轮的固定顺序

```
open_parent → read_public → plan → measure_parent → build_candidate
→ measure_candidate → decide → record → consult_the_model → submit → finish
```

三条顺序上的硬约定（各有一处代价支撑）：

1. **父模型先测** — 候选永远与父模型的**自身读数**比，而不是与历史最优比。
   每一轮都是可归因的局部改进，不会因历史最优不可复现而回退。
2. **判决先于问模型** — 模型是对**已做出的判决**的复核，不是判决的输入。
   否则模型的一次幻觉就会直接改变选型。
3. **落账先于提交** — 账本、SwanLab、模型回执三者先写盘，再交工件。
   即使提交后崩溃，证据链仍完整。

### 2.3 两层受控自进化

- **模型层自迭代**：候选是父模型的**精确副本**（权重、Adam 动量、epoch 计数、
  归一化状态全部继承），只有训练过程被假设改变 ⇒ 效果可精确归因到那一个改动。
- **策略层自改进**：假设库、度量口径、护栏、epoch 预算由策略层决定，
  **不由模型决定**。模型只负责复核读数与建议下一步。

### 2.4 受控机制（四道闸门）

| 闸门 | 实现 |
|---|---|
| 父模型只读 | 经 `rnd.parent.path` 打开并校验平台声明摘要，绝不写回 |
| 度量护栏 | 主指标劣化 > +5% 一律不采纳 |
| 方向一致性 | 分数变好但方向非假设所预测 → 判为**证伪**，不采纳 |
| 受控预算 | epoch 预算由轮次严格递增且有上限，策略层决定 |

## 3. 漂移监测与归因

系统的漂移信号不是靠统计分布距离，而是靠**判决结果本身**：

- **父模型读数 vs 候选读数的差** → 直接量化「本轮改动是否让模型在新分布上更好」。
- **假设的证伪条件** → 每个假设自带「什么观察会推翻它」，归因是**预先声明**的，
  不是事后编的。
- **切片度量作为漂移的旁证** → C 方向的 `late_rmse`（$y \le 200$）仍然被测量
  并写进账本，用于观察「早期/中后期的表现是否分化」，但**不参与裁决**（§4）。

C 方向还有一个**尺度无关的退化度**信号：

$$w = 1 + \alpha \cdot (1 - y/u_{\max}),\qquad \alpha = 0.5$$

其中 $u_{\max}$ 是该引擎的寿命上界。$w$ 度量的是**相对**退化程度，因此不同
寿命尺度的引擎（有的寿命 80 分钟，有的 3000 分钟）按同一条退化路径被对待。
经验上 `deg` 加权与不加权在统计上不可区分（Wilcoxon $p = 0.68$）——
**真正的收益来自剪掉绝对阈值**，不是来自加权本身。

## 4. 核心创新：C 方向选型口径的根因定位与修复

### 4.1 现象

平台实测（v5）：C 方向隐藏测试 RMSE **56.25329**，官方静态基线 **52.8686**，
**劣化 +10.06%** —— 违反基础门槛「不低于静态基线」。

### 4.2 初始假设与它的脆弱之处

我们最初假设「隐藏测试协议是早期寿命截断 ⇒ 应该用截断切片（$y \le 90$）
选型」。这个假设**从未被验证过**。

反向工程支持了它：在公开验证集上统计 $y \le 90$ 得 **9 646** 条，平台隐藏
测试规模经反推为 **9 687** 条，偏差仅 0.4%。**但规模对得上不等于度量对得上。**

### 4.3 判决性实验：12 折留一轴承交叉验证

构造 12 折「留一引擎」严格交叉验证：每折用一个子集选型，用**完全未参与
选型**的另一个子集做真实评测。测 7 种截断阈值：

| 截断切片 | 与真实留出集 RMSE 的 Spearman 相关 |
|---|---|
| $y \le 50$ | −0.31 |
| $y \le 75$ | −0.42 |
| $y \le 90$ | −0.47 |
| $y \le 100$ | −0.50 |
| $y \le 120$ | −0.53 |
| $y \le 150$ | −0.53 |
| $y \le 200$ | −0.53 |

**全部为负。** 按切片选型在 12 折里 **12/12** 都选中 `cap150`，而它在留出
引擎上**排名倒数第一**（11/11 折，RMSE 73.73 vs 基线 59.87）。
按**全量 RMSE** 选型：$\rho = +1.0$，平均排名 **1.00**，**7/12** 折优于基线。

### 4.4 机理

绝对阈值（$y \le 90$）把**长寿命轴承的中段**误判成寿命末期。一根寿命
3000 分钟的轴承在 $y=90$ 时仍健康中期，但在截断切片里它与一根寿命
80 分钟、已报废的轴承**长得一模一样**。切片丢失尺度信息，把不同寿命尺度的
引擎混为一谈 ⇒ 用它选型，等于**系统性地选最差的候选**。

### 4.5 修复（三处）

1. **判决口径改为全量 RMSE**：截断切片降级为**只记录、不裁决**（`compare_joint`
   现在只在 `primary_value` 上做判决；切片无否决权，也无力挽救回归）。
2. **全量护栏 5%**：候选若让全量主指标劣化 > +5%，即使切片变好也不采纳。
3. **相对退化度加权**替代绝对阈值加权（`profile_c.weight_horizon() → None`）。

### 4.6 附带发现：epoch 预算不足

15 个 epoch 是欠训练，掩盖在错误口径后面。把基础预算从 15 提到 65
（C ×0.5 → 32–75）：

| epoch 预算 | 留出集 RMSE 改善 | 胜出折数 | p 值 |
|---|---:|---|---|
| 40 | −0.624 | 10/12 | 0.0024 |
| **80** | **−0.655** | **11/12** | **0.034** |

## 5. 实验规范与对照实验

### 5.1 三重记录

| 记录 | 路径 | 内容 |
|---|---|---|
| 账本 | `runs/harness-offline/ledger.jsonl` | 30 轮，每轮含假设/改动/证伪条件/父子读数/判决/护栏/模型回执/历史 ID |
| SwanLab | `runs/harness-offline/swanlab/{A,B,C}-round-N.jsonl` | 同源逐轮记录，可上传云端 |
| 汇总报告 | `runs/harness-offline/run_report.json` | 3 方向 × 10 轮 |

账本条目的 `history_ids` 证明**读了历史**，`change` + `primary_before/after`
证明**做了实验**，`verdict` + `adopted` + `reason` 证明**依据结果做了决策**。

### 5.2 对照实验设计

| 实验 | 设计 | 结论 |
|---|---|---|
| 选型口径 | 12 折留一引擎交叉验证，7 种切片 vs 全量 | 切片全负相关；全量 $\rho=+1.0$ |
| epoch 预算 | 10 / 20 / 40 / 80 四档，同一 12 折 | 40–80 显著优于 15 |
| 退化度 α | 相对退化度系数扫描 | 与不加权不可区分（$p=0.68$） |
| 规则候选集 | 小样本规则筛选 | 用于确定候选假设族 |
| 平台验证 | v5 / v6 / v8 逐版试运行 | 定位并修复根因 |

所有实验的原始结果保存在 `artifacts/tracks/*.json`，方法论论证见
`docs/SELECTION_SLICE_ROOT_CAUSE_20261124.md`。

### 5.3 结果

| 方向 | 指标 | 基线 | 首轮 | 末轮 | 采纳轮数 |
|---|---|---|---|---|---|
| A | Macro-F1 ↑ | 0.7140 | 0.7140 | **0.7410** | 7/10 |
| B | RMSE ↓ | 681.16 | 681.16 | **456.42** | 9/10 |
| C | RMSE ↓ | 52.8686 | 39.92 | **37.44**（全量 51.34 → 第 10 轮 50.63） | 3/10 |

C 方向采纳率低（3/10）是**正确行为**：诚实的判决门槛下多数假设被证伪并
被拒绝，父模型被保留。旧口径下 C 采纳率高，换来的是隐藏集 −10.06% 的劣化。

平台实测（v5）：A Macro-F1 0.87572（**+20.96%** vs 基线 0.7240）、
B RMSE 609.08（**+10.58%**）、C RMSE 56.25329（**−6.40%**，已修复）。

## 6. 安全与工业落地

| 要求 | 落实 |
|---|---|
| 无恶意代码 | 镜像只有一个入口 `/app/harness.py`，源码全开源可审 |

## 7. 结论与展望

本项目交付的是一套**可审计、可归因、可回滚**的工业模型自进化系统：

1. **架构**：分层 + 固定轮序 + 三重记录，把「受控自改进」落成可检查的代码结构；
2. **方法**：12 折留一交叉验证定位并修复了一个反直觉的度量根因，
   把 C 方向选型从「12/12 折倒数第一」翻转为「平均排名 1.00」；
3. **工程**：10 轮 × 3 方向全部真实执行，平台侧 A、B 已有 +20.96% / +10.58%。

**最重要的经验**：在工业自进化系统里，最危险的不是模型不够强，而是
**度量选错了却还在自信地优化**。留出验证、护栏与证伪机制把这类错误变成
可被发现的工程事实，而不是一次看不见的 −10%。

**下一步**：把 12 折留一验证做成**每轮在线执行**的自检（当前只在开发期
离线执行），让系统能在线发现「自己的口径失配」；并把归因从「单假设」
扩展到「多假设交互」。
