## 四、提交材料（平台原文）

> 镜像和源码、模型调用信息、实验记录链接，以及**设计说明、技术报告（不超过 10 页）、
> 演示视频（不超过 5 分钟）和来源声明**。**平台没有单独入口的材料请随作品文档提交或提供链接。**

这条原文很重要：平台表单只有「作品文档」一个文件入口
（对应规则表的 34 行「模型配置」），所以
**技术报告、演示视频说明、来源声明必须放进「作品文档」**，
或者提供链接。

## 五、平台表单的硬性大小限制（前端代码实测）

| 上传项 | 限制 | 代码原文 |
|---|---:|---|
| **作品文档**（模型配置） | **2 MiB** | `if(s.size>2097152){f(\`作品文档不能超过 2 MiB。\`);return}` |
| 数据文件（JSONL） | 64 MiB | `请选择非空 JSONL 文件，最大 64 MiB。` |
| 候选/状态文件数 | 单次 64 个文件，合计 512 MiB | 平台 SDK 文档 |

> **注意**：规则表写的是「模型配置 ≤ 50M」「Harness 镜像 ≤ 50M」，
> 但平台前端对**作品文档**实际强制 **2 MiB**。
> 我们的模型配置只有约 9 KB，远在两个限制之内。
>
> 镜像方面，规则表注明「超过 50MB 时，上传网盘链接」；
> 平台前端**没有**对镜像大小做客户端校验，实际已成功接收
> 182,732,800 字节（174.3 MiB）的 tar，`status: ready`。
> 保险起见，网盘链接作为**备选**在提交清单里给出。

## 六、SDK 侧的三条硬约束（影响架构设计）

从平台 bundle 里带出的 SDK 说明（1.0.4）：

1. **提交候选时**：
   ```python
   submitted = rnd.submit_candidate(
       candidate_dir,
       hypothesis="本轮假设",              # 非空，<= 4000 字节
       change_summary="相对父模型实际改了什么",  # 非空，<= 4000 字节
       configuration={"epochs": 1},        # 对象，序列化 <= 64 KiB
       seed=1,                             # 整数
       checkpoint_paths=["checkpoint.npz"],
       code_paths=["baselines/model.py"],
       predict_argv=["python3", "/app/harness.py", "predict"],
   )
   ```
2. **RPC 结果未知时不得重试**：RPC 发出后若被信号、超时或异常中断，
   宿主是否已处理该请求**未知**。此轮会话不再可用，后续 RPC 报
   `RPC_OUTCOME_UNKNOWN`，**不会发送新请求、消费迟到响应或自动重试**。
   不要捕获中断后继续调用。
3. **状态保存**：先复制再写 `/workspace/state`；`/state` 本身只读。

> 第 2 条与本项目 v8 试运行失败的诊断相互印证：平台侧对
> **上游 504 的处理策略就是「不自动重发」**，并在账本里保留原请求状态。
> 我方 `_call_model()` 的 3 次重试发生在**同一次宿主调用内部**，
> 与平台说的「不自动重发该请求」不冲突，但也意味着一次 504 会终止整轮。

## 七、评测机制（决定了我们的架构）

> 工业模型从平台提供的检查点开始，在 CPU 环境中续训。每个数据集进行 **10 轮**优化，
> 最终使用隐藏测试数据评测。
> Harness 调用 PyTRiO 大模型来读写代码、使用工具；**评分对象是续训后的工业模型**。
> 大模型参数量不超过 27B，可使用微调后的 Sampler，或提交页允许的官方基础模型。

关键推论：

- **评分对象是工业模型，不是大模型**。27B 的职责是驱动 Harness（读历史、
  做实验、决策），**不参与最终打分**。
- **10 轮**的预算意味着 epoch 预算必须前紧后松地分配，不能平均用力。
- **CPU 环境续训** → 镜像内不得依赖 GPU 专属算子。

## 八、数据集与指标（平台原文）

| 方向 | 任务 | 指标 |
|---|---|---|
| A | UCI Gas Drift | Macro-F1 越高越好 |
| B | 轴承 RUL | 以剩余寿命量化退化，单位分钟；RMSE、MAE 越低越好 |
| C | 发动机寿命 | 剩余寿命，单位循环；RMSE 越低越好，参考 NASA 非对称评分 |

> C 方向平台明确提示「**参考 NASA 非对称评分**」——这印证了平台在 C 方向
> 的评估本身带有非对称权重，而我们实验发现的「绝对阈值切片与真实健康度
> 负相关」正是这一非对称性的陷阱：我们用全量 RMSE 判决，正是为了让
> 优化目标与平台的非对称评分**方向一致而不冲突**。
