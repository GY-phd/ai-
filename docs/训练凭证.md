### 2.1 B 方向的三协议对照

单一切分上的胜负会被单根轴承的寿命尺度左右，所以 B 方向同时报告三个口径：

| 协议 | 官方基线 | 智训引擎 | 相对变化 | 胜出单元 |
|---|---:|---:|---:|---:|
| 官方切分（3 根轴承） | 681.16 | 716.72 | −5.2% | 2 / 3 |
| 留一轴承（9 折） | 761.25 | **389.32** | **−48.86%** | 8 / 9 |
| 全新工况（3 折） | 802.85 | **501.65** | **−37.52%** | 3 / 3 |

官方切分口径下我们**不如**官方基线——这是诚实的：只有 3 根留出轴承，
误差由单根轴承的寿命尺度决定（我们在 Bearing1_4 / Bearing2_4 上大幅领先，
在 Bearing3_4 上落后 6.1%）。隐藏测试集是**整根轴承隔离**的，
所以后两个口径才是它的正确代理。

复现：`python -m research.tracks.track_b_final --out artifacts/tracks/track_b_final.json`

### 2.2 模型侧受控消融（留一轴承 9 折）

同一套代码、同一协议、同一随机种子，每次只改一个变量。
官方基线在**同样的每一折上重新拟合**，所以每一行都是同口径比较。

| 方案 | 特征变换 | 激活 | 目标缩放 | 宽度 | LOBO RMSE | 相对基线 |
|---|---|---|---|---:|---:|---:|
| 官方静态基线（逐折重拟合） | — | — | — | 32 | 761.25 | — |
| raw + tanh + 缩放 | raw | tanh | 是 | 96 | 732.84 | +3.73% |
| raw + tanh + 不缩放 | raw | tanh | 否 | 96 | 780.87 | −2.58% |
| slog + tanh + 不缩放 | slog | tanh | 否 | 96 | 743.24 | +2.37% |
| eng34 + tanh + 缩放 | eng34 | tanh | 是 | 96 | 685.99 | +9.89% |
| **eng34 + tanh + 不缩放** | eng34 | tanh | 否 | **96** | **639.52** | **+15.99%** |
| eng34 + relu + 不缩放 | eng34 | relu | 否 | 128 | 740.08 | +2.78% |

**负结果也保留**：`raw + tanh + 不缩放` 比 `raw + tanh + 缩放` **更差**——
「不缩放目标」只有在特征变换正确时才占优，两者必须一起改。
ReLU 在同一协议下并不占优（740.08 vs 639.52），
而且官方参考加载器把 `hidden ≤ 128` 与 `np.tanh` 写死了，
所以保留 tanh 与宽度 96 是**能被官方加载器读出来的次优**。

复现：`python -m research.exp_fusion --out artifacts/fusion_ablation.json`

## 3. 零泄漏协议

这是本次系统最重要的约束，逐条可查（见 `runs/{A,B,C}/run_report.json` 的
`stream_meta`）：

- **判定集（judge）** 是整根轴承 / 整台发动机的留出，从不参与任何拟合。
  每个周期的候选模型与冠军模型都在**同一批**留出单元上打分，
  所以"增益"读的是模型，不是切片的难度。
- **验证集只评一次**，在闭环的最后，且从不参与训练、标准化统计量或目标缩放。
- **A 方向**：公开训练集只有一个批次，按时间切开会等于按类别切开
  （批次内部按类别排序，实测前 60% 只有 3 个类别）。因此流改为**按类别分层**的
  40%，判定集从验证批次分层留出 25%，验证集剩余部分最后评一次分。
  这条修复把 A 的 Macro-F1 从 0.3766（按时间切）拉回 0.7224（分层切）。
- **早先版本把验证批次当流**，训练完再在验证集上评分，报出 Macro-F1 0.9760——
  那是**从测试集偷来的分**。修复后同一系统给出干净的 0.9707。
- **最终模型用全部训练单元重训**（初始 + 流 + 判定集，不含验证集）。
  闭环本身在**故意留出**的切分上跑，是为了让门控有判定集；
  配方在留出集上选出，所以选择是诚实的，只有最后一次拟合拿到了全部数据。

### 4.1 可复现步骤

> 下列命令复现的是**研究运行时**（`evo`）的实验，用于核对本文记录的数字。
> **平台的正式评测入口不是它们**，而是
> `python3 /app/harness.py describe|train|predict`。

```bash
# 0) 环境自检（依赖/数据/合规）
python -m evo doctor

# 1) 跑完整自进化闭环（官方数据）
python -m evo run \
  --set data.task=regression \
  --set data.profile=B \
  --set paths.data_root=<赛题包>/public \
  --set data.train_file=train.jsonl \
  --set data.valid_file=validation.jsonl \
  --set data.format=jsonl \
  --set paths.artifacts_root=artifacts/official

# 2) 门槛自检（≥3 次迭代 + 不低于官方静态基线）
python -m evo gates --set paths.artifacts_root=artifacts/official

# 3) 与官方 checkpoint 直接比对
python scripts/compare_official_baseline.py --artifacts artifacts/official

# 4) 审计链完整性 + 实验记录合规
python -m evo verify-audit --set paths.audit_log=artifacts/official/audit/audit.jsonl
python -m evo compliance --set experiment.local_dir=artifacts/official/exp

# 5) 打包（自动排除权重）
python scripts/build_submission.py --out dist/submission
```

固定随机种子由 `runtime.seed` 控制（默认 `20261105`）。同一份数据 + 同一随机种子
+ 同一配置 ⇒ 同一结果。

### 4.2 B 方向自适应最终模型（提交包口径）

`evo` 的产物在 `artifacts/official/`，分数口径是
`compute_metrics()["score"]`，回归任务下等于 **−RMSE**（越小越好）。

**门槛自检**（`run_summary.json` 的 `gates` 字段，`all_passed = true`）：

| 口径 | 官方静态基线 | 本系统 | 说明 |
|---|---:|---:|---|
| tail（主判定） | −1 050.30 | **−239.46** | 流后 1/3 段平均分 |
| overall | −1 546.16 | −667.66 | 全程平均分 |
| best（单次最佳） | — | −174.26 | 历史上最好的一个版本 |

**逐窗口在线曲线**（`online_curve.json`，分数 = −RMSE）：

| 窗口 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|
| 自适应（本系统） | −2 175.0 | −660.9 | −317.1 | −374.0 | −174.3 | −304.7 |
| 静态基线（同批冻结） | −2 175.0 | −1 924.6 | −1 664.9 | −1 411.8 | −1 170.7 | −929.9 |

这张曲线是「自适应」这件事本身最直接的证据：**两条线从同一起点出发，
静态基线一路退化（−2 175 → −930），自适应则在第 5 个窗口追平历史最好（−174.3）**。
静态基线之所以一路变差，是因为它的分数是冻结模型在新批次上的表现，
而批次随时间推移，轴承的工况分布也在变。

逐版本的模型元信息（参数、超参、指标、版本号）留档在
`artifacts/official/models/v*.json`，6 个版本全部可回滚，
审计哈希链在 `artifacts/official/audit/audit.jsonl`。

> 复算命令见 §4.1；门槛与曲线落 `run_summary.json` 与 `online_curve.json`。

## 5. 门槛自检口径说明

赛题原文：「最终模型性能不得低于官方提供的静态基线」。
系统同时报告三个口径，**主判定用第一个**：

| 口径 | 含义 | 适用性 |
|---|---|---|
| **holdout（主判定）** | 最终上线模型 vs 静态基线，在**独立留出轴承**上评估 | 复现官方"整根轴承隔离"的隐藏测试条件 |
| tail（参考） | 流后 1/3 段平均分对比 | 反映长期维持能力；但若流末尾恰逢寿命远长于训练集的轴承，会被尺度效应污染 |
| overall（参考） | 全程平均分对比 | 最稳健，但掩盖尾段退化 |

`holdout` 口径的双重留出保证：留出轴承**既不在初始训练集，也不在漂移流里**；
官方验证集的轴承同样与训练集、留出集不重叠。

## 6. 训练过程的合规声明

- **数据边界**：训练只使用公开 `train.jsonl`；验证集仅用于评估，**不参与**
  任何拟合（包括标准化统计量与目标缩放）；漂移流用训练轴承的留出集，
  与初始训练集零重叠（审计日志 `stream_built_by_bearing_holdout` 留痕）。
  三方向闭环的等价保证写在各 `run_report.json` 的 `stream_meta` 里：
  `unit_leakage` / `validation_used_for_training` / `judge_used_for_training`
  三个字段都必须为 `false`。
- **输入白名单**：仅使用 `inputs` 展开后的数值特征；轴承编号、快照序号、
  总快照数、目标值、归一化寿命一律**不入模**（官方 loader 亦会拒绝）。
  A 方向的「已运行循环数」是显式特征（`extra_features="elapsed"`），
  由 C 方向的假设检验引入并被门控接受。
- **资源**：4 核 CPU，无 GPU；所有模型 `n_jobs=4`；训练全程无外联。
- **模型权重**：产物中保留全部版本（可回滚），但**提交包自动剔除**
  （`.pkl/.pt/.npz/.bin/.joblib` 等），打包脚本会校验权重文件数为 0。
  GitHub 仓库包同样为 0 权重（`tools/verify_repo.py` 会强制校验）。
