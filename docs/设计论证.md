# 设计论证

> 对应赛题评审的「方案价值 35 分」与「专家评审 55 分」。
> 本文说明**为什么这样设计**，以及每个设计决策背后的取舍与证据。

## 0. 赛题的核心矛盾

赛题要求构建「工业模型自进化系统」，本质是一个**受约束的在线优化问题**：

```
在漂移的数据流上，持续决策「要不要更新模型、怎么更新」，
使得长期性能不劣于静态基线，同时成本可控、过程可审计。
```

三个约束同时成立，缺一不可：

| 约束 | 赛题原文 | 系统对应机制 |
|---|---|---|
| **不得低于基线** | 「最终模型性能不得低于官方提供的静态基线」 | 冠军-挑战者 + 影子评估 + 统计显著性 + 自动回滚 |
| **至少三次真实迭代** | 「至少包含三次尝试迭代过程」 | 漂移触发 + 门槛探针；四段式证据链留痕 |
| **无人干预可复现** | 「无人工干预完成封闭评审全部阶段」 | 确定性降级 + 全自动裁决 + 审计哈希链 |

## 1. 受控 RSI：两层自迭代

赛题 PPT 明确定义「受控 RSI（Recursive Self-Improvement）」为两层：

```
第一层 | 模型自迭代
  更新工业模型参数: 校准阈值、增量学习、扰态惩罚
  目标: 对抗数据与场景漂移

第二层 | 策略自改进
  利用历史实验修订更新时机、调参与工具/Skill 或驱动模型
  目标: 越跑越聪明, 减少无效优化
```

### 1.1 第一层：模型自迭代

每轮闭环（五步，赛题 PPT 原文顺序）：

```
漂移监测 → 诊断归因 → 实验优化 → 评估上线 → 回流迭代
```

- **漂移监测**：PSI（分位分箱）+ KS 检验，判定协变量漂移
- **诊断归因**：区分 `covariate` / `concept` / `mixed` / `covariate_weak`
- **实验优化**：模型层重训 + 策略层调参（并行探索多个候选）
- **评估上线**：影子评估（独立留出窗口）+ 配对统计检验
- **回流迭代**：未通过则拒绝上线；上线后若后续窗口表现恶化则回滚

### 1.2 第二层：策略自改进

这是**区分「自适应系统」与「自动化脚本」的关键**。策略层用
**受限 Thompson Sampling Bandit** 在线学习两个决策参数：

| 参数 | 含义 | 为什么值得在线学 |
|---|---|---|
| `psi_trigger` | 触发更新的漂移阈值 | 阈值过低 → 更新过频 → 单位收益低；过高 → 漏检 → 收益为零 |
| `min_gain` | 上线所需的最小增益门限 | 过低 → 噪声级抖动被当成改进；过高 → 真实改进被拒 |

「受限」的含义：每个参数只在**相邻离散档位**间移动
（`max_param_shift=1`）。这是刻意的约束——

> 无限制的在线调参会滑向「专为当前流优化」的过拟合解。
> 限制单次移动幅度，使策略的演化可解释、可审计、不会突然崩塌。

**奖励设计**（这是最容易做错的地方）：

```
reward = 影子得分增益 / (1 + 归一化成本)
```

- 分子用**绝对量纲**的增益 → 跨轮可比，反映"这次更新到底让现网好了多少"
- 分母含成本 → 高成本更新被自然惩罚
- **不能用 efficiency 直接当奖励**：回归任务 score 是 `-RMSE`（负数），
  早期量级只有 1e-3，不同阈值之间几乎没有可分辨的差异

## 2. 关键设计决策与取舍

### 2.1 指标口径必须对齐官方，否则优化错误目标

官方 `baselines/docs/{A,B,C}.md` 定义了三个 profile 的评分口径：

| profile | 主指标 | 辅助 |
|---|---|---|
| A 气体分类 | **Macro-F1** | Accuracy、混淆矩阵 |
| B 轴承 RUL | **RMSE** | MAE |
| C 发动机 RUL | **RMSE** | MAE、**NASA 非对称分数** |

**取舍**：最初按 PPT 的概括为 B 包设计了「严重退化漏报」否决权。
读到官方 TASK.md 后发现原文明确「**不以严重故障漏报率评价本任务**」——
若把漏报率并入 score，系统会去优化一个**不被评分**的量，
反而损害真正的主指标 RMSE。**这是典型的「优化了错误目标」**，已修正。

修正后的做法：
- 漏报率降级为**可选诊断指标**，不进 score、不否决上线
- C 包的 NASA 非对称分数用**官方公式**（逐样本惩罚之**和**，高估惩罚是低估的 5 倍）
  —— 官方说明该分数不可跨样本数横比，因此不能取均值冒充

> **方法论**：赛题材料（PPT 概述）与赛题包（官方 docs）冲突时，
> **以官方包为准**。PPT 是培训概览，赛题包才是评分依据。

### 2.2 留出策略决定了系统是否被"自己制造的问题"打败

公开包的 9 根训练轴承寿命跨度极大（RUL 0~122 到 0~2537）。

**错误做法**：把最长的两根轴承全拿去做漂移流。后果是训练集 RUL 上限只剩 ~532，
而流末尾是 0~2537 —— 模型从未见过那个尺度，尾段 RMSE 必然爆炸，
自适应与静态基线**双双崩掉**。这不是自进化失败，而是留出策略制造的
训练/评测尺度失配。

**正确做法**：按寿命**分层交错**抽样，让留出集既有长寿命（提供足够流长度）
也有短寿命（尺度接近训练集），同时训练集保留长寿命轴承覆盖完整尺度。

### 2.3 轴承标识必须用全名，不能用 `split("_")[-1]`

轴承名形如 `Bearing3_1` / `Bearing1_1` —— `split("_")[-1]` 把两者都映射成 `"1"`。
用短 id 做排除键会**误伤**：选中 `Bearing3_1` 时 `Bearing1_1`、`Bearing2_1`
也被踢出训练集，白白损失大量数据；审计记录里的轴承名单也会失真，
让泄漏检查给出错误结论。

### 2.4 门槛判定用三口径，主判定用 holdout

赛题原文「最终模型性能不得低于官方提供的静态基线」。

| 口径 | 特点 | 角色 |
|---|---|---|
| **holdout** | 独立留出轴承，复现官方"整根轴承隔离"的隐藏测试条件 | **主判定** |
| tail | 流后 1/3 段 | 参考（会被流尾尺度效应污染） |
| overall | 全程平均 | 参考（掩盖尾段退化） |

holdout 具备**双重留出**：留出轴承既不在初始训练集，也不在漂移流里；
官方验证集轴承同样与二者不重叠。这最贴近官方评测条件。

### 2.5 路线二（PyTRiO 后训练）必须被放行

赛题 PPT 给出两条路线：路线一直接用指定基模；路线二以千问为基座经
PyTRiO 后训练获得驱动模型。

后训练模型名通常带后缀（`qwen3.8-27b-ft-20261115`）。若白名单只做字面相等校验，
会把**合规**的后训练模型误判为违规，把路线二参赛者卡在自己代码里。

本系统的白名单分三层：显式豁免（`derived_models`）→ 基座包含 → 拒绝且不发起调用。

### 2.6 特征 schema 必须严格校验

官方 loader 逐条比对 `flatten` 产生的字段路径，不一致直接报错。
这是**最难查的一类 bug**：模型照常输出数字，但数值全是错的。

因此训练时把 schema 路径随模型持久化，推理时逐条比对；
官方协议适配器在 schema 不符时明确报错而非静默降级。

## 3. 为什么这套设计能赢

### 3.1 客观分：效果

在官方验证集（3 根轴承，1679 样本）上，与官方 `checkpoint.npz` 直接比对：

| 系统 | RMSE（分钟） | MAE（分钟） |
|---|---|---|
| 官方静态基线（NumPy MLP, 865 参数） | 681.16 | 563.11 |
| 我们的静态基线 E0 | 625.92 | 491.14 |
| **我们的自适应最终模型 E3** | **464.70** | **366.34** |
| **相对官方静态基线** | **−31.8%** | **−34.9%** |

### 3.2 客观分：可复现与可审计

- 每轮迭代留「读历史 → **可证伪**的假设 → 实验原始数字 → 决策理由」四段式证据链
- 全事件 SHA-256 哈希链审计（追加写、不可篡改）
- `python -m evo verify-audit` 一键校验

### 3.3 主观分：安全可控与工业落地

| 赛题关注点 | 系统机制 |
|---|---|
| 安全可控 | 影子评估 + 配对显著性 + 门限 + 自动回滚 + 熔断 |
| 成本收益 | 多维成本收益报告（算力/标注/token 单位增益 + 触发命中率） |
| 工业语义 | 指标口径对齐官方；回归用 MAE 而非 `!=` 比较 |
| 资源效率 | 4 核 CPU 约束、线程限流、离线性保证 |
| 无人干预 | LLM 不可用时确定性降级，闭环照常 |

### 3.4 主观分：实验规范与分析深度

`scripts/compare_systems.py` 提供 E0/E1/E2/E3 四系统 × 多随机种子的对照，
含配对 t 检验、Wilcoxon 符号秩检验与逐种子胜率；
`scripts/compare_official_baseline.py` 直接与官方 checkpoint 比对。
种子数少（3 个）时配对检验力有限，因此**同时报告三种证据**，
避免只凭单一 p 值下判断。

## 4. 已知局限与后续工作

| 局限 | 现状 | 后续 |
|---|---|---|
| RUL 回归 R² 仅 0.004 | 绝对精度仍低（RMSE 465 分钟 vs 寿命尺度 0~2537） | 引入分段/曲线型 RUL 估计器；利用 snapshot 序号做单调约束 |
| 尾段口径不稳定 | 受流末尾轴承尺度效应污染 | 已降为参考口径；可改为"按轴承归一化 RMSE" |
| 非对称分数未参与打分 | 官方 C 包主指标仍是 RMSE | 若官方确认非对称分数计入总分，再纳入 score |
| LLM 决策仅用规则兜底 | 无 PyTRiO 服务时确定性降级 | 接入后训练模型后可让 LLM 提出超参建议 |

## 5. 一句话总结

> 我们没有让系统"跑得更久"，而是让它**优化正确的目标**、**在正确的尺度上评估**、
> **在证据上做决策**——这三件事的乘积，才是赛题所说的"长期稳定、可复现、可审计、
> 安全可控、资源高效"。
