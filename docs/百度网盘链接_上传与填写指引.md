## 六、如果想在不冒风险的前提下把体积压到 50 MB 以下

**当前不推荐**，但方案与风险如下：

| 方案 | 预估体积 | 风险 |
|---|---:|---|
| A. `python:3.12-alpine` + numpy | ~45–55 MB | musl 与 numpy 的 ABI 兼容性需重验；**OpenBLAS 线程行为改变浮点归约顺序 ⇒ 结果不可复现** |
| B. 静态链接 numpy 的 manylinux wheel | ~70–90 MB | 仍带 slim 基础层 77 MB，**降不到 50 MB** |
| C. 精简 slim 基础层（去测试/文档） | ~130 MB | 收益有限、风险低，但**仍超 50 MB** |

**体积构成（实测）**，供判断：

| Layer | 大小 | 内容 |
|---|---:|---|
| `python:3.12-slim` 基础层 | 77.5 MB | Python 运行时 |
| `zhixun-engine-deps` | 55.9 MB | numpy 28.2 + numpy.libs 26.8 MB |
| 其它基础层 | 40.3 MB | 系统文件 |
| **`zhixun-engine`（我们的代码）** | **0.5 MB** | 全部参赛实现 |

> **我们自己的代码只有 0.5 MB。** 174 MB 里 99.7% 是 Python 运行时和 numpy。
> 减重的唯一有效路径是换基础镜像，而那会牺牲数值可复现性。
