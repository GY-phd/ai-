# 选型口径与训练加权的根因分析（2026-11-24）

> 结论先行：**隐藏集的 +10.06% 偏移不是"口径不对"，而是"用截断切片做选型"这个动作本身在选错模型。**
> 任何截断口径的切片与留出集真值**负相关**；用它们选型会稳定地选出**最差**的候选。
> 修复：切片降级为记录，**全量验证 RMSE 单独决策**；训练权重从"绝对阈值"改为"相对退化度"。

本文档记录 2026-11-24 的完整实证过程、结论与代码改动。

| 平台公开验证（C，全量口径） | 51.111160 | 2026-11-23 试运行 r5 |

## 2. 关键新证据：隐藏集的行数

平台报告里写着隐藏测试 **9 687** 个样本。公开验证集有 **23 049** 行（106 台发动机）。
两者差距巨大，说明**隐藏指标本身就是一次截断**。

在公开验证集上扫描截断口径：

| 口径 | 行数 | 与 9 687 之差 |
|---|---|---|
| `y <= 50` | 5 406 | −4 281 |
| `y <= 75` | 8 213 | −1 474 |
| **`y <= 90`** | **9 646** | **−41（0.42%）** |
| `y <= 100` | 10 706 | +1 019 |
| `y <= 150` | 15 942 | +6 255 |
| `y <= 200` | 19 762 | +10 075 |
| 全量 | 23 049 | +13 362 |

`y <= 90` 与 9 687 只差 41 行。这不是巧合——**隐藏集确实是一次截断，截断点大约在 y ≈ 90**。

但这带来一个致命的推论：

> 现行选型切片 `late_rmse` 取的是 `y <= 200`，覆盖的是**中晚期**。
> 隐藏集若只评 `y <= 90`（**早期**），那两者几乎不重叠。
> **切片在优化一个隐藏集几乎不评分的区域。**

## 3. 决定性实验：哪个切片能预测留出集

`research/tracks/c_horizon.py`：**12 折留一发动机**（2 seed × 6 折），11 个候选配方，
在**训练时从未见过的发动机**上，测量每个截断口径与留出集全量 RMSE 的排序相关性。

### 3.1 排序相关性（Spearman ρ）

| 切片 | ρ | 负相关折数 |
|---|---|---|
| `y <= 50` | −0.274 | 10/12 |
| `y <= 75` | −0.464 | 9/12 |
| `y <= 90` | −0.499 | 9/12 |
| `y <= 100` | −0.511 | 9/12 |
| `y <= 120` | −0.532 | 9/12 |
| `y <= 150` | −0.534 | 9/12 |
| **`y <= 200`（现行切片）** | **−0.392** | **9/12** |
| `y <= 250` | +0.269 | 3/12 |
| **全量口径** | **+1.000** | **0/12** |

**每一个截断切片都是负相关的。** 唯一的例外 `y <= 250` 转正，恰恰因为它已经接近全量。

### 3.2 用切片选型会选出什么

| 按哪个指标选 | 选出候选在留出集上的名次（11 个候选） | 赢基线 |
|---|---|---|
| `y <= 50` | 9.42 / 11 | 1/12 |
| `y <= 90` | **11.00 / 11** | **0/12** |
| `y <= 150` | **11.00 / 11** | **0/12** |
| **`y <= 200`（现行）** | **10.17 / 11** | **0/12** |
| `y <= 250` | 5.67 / 11 | 4/12 |
| **全量口径** | **1.00 / 11** | **7/12** |

用现行切片选型，选出的候选**平均排在第 10 名**（11 个里倒数第 2），**12 折里 0 折赢基线**。
用全量口径选型，**平均第 1 名**，**12 折里 7 折赢基线**。

### 3.3 机理：为什么切片会稳定选错

按 `y <= 90` 切片选出的候选，在 **12/12 折**里都是 `cap150` 配方。
而在留出集全量口径上，`cap150` 是**垫底**的：

```
折 (seed=7, fold=2):
  cap150   full 73.7348   h90 24.1086   ← 切片最优，全量最差
  deg0.5   full 59.9382   h90 33.0820   ← 全量最优
  基线     full 59.8696
```

机理是**结构性的**：截断切片覆盖的，正是某个配方训练权重所集中的区域。
所以该配方**按构造**赢得切片，同时在切片看不见的地方损失精度。
这不是巧合，是设计出来的必然。

**绝对阈值权重（`surv`/`cap`）还有第二个致命缺陷**：
`y > 150` 这种绝对阈值，会把一台 400 循环发动机的**中段**误判为末期，
却把一台 500 循环发动机的**开头**判为新鲜。它标注的根本不是"退化程度"，而是"绝对数值"。

## 4. 改动

### 4.1 判决逻辑：切片降级为记录

`contest_baselines/layers/model/metrics.py`

- `compare_joint()`：**只按 `primary_value`（全量验证 RMSE）判决**。
- 切片仍被测量、仍写进 ledger 与 `as_record()`，两个读数不一致时**记录下来**供审计，
  但切片**不能否决**全量的改善，也**不能挽救**全量的退化。
- `compare()`：从比较 `selection_value` 改为比较 `primary_value`，与 `compare_joint` 一致。
- `CONFLICT` 保留为可报告状态，但不再是判决输入。

`contest_baselines/layers/controller/round.py`：同步更新说明。

### 4.2 训练权重：绝对阈值 → 相对退化度

新增假设 `the-degradation-is-relative`
（`contest_baselines/adapters/hypotheses.py`）：

```
w = 1 + alpha * (1 - RUL / unit_lifetime)
```

- **无绝对阈值**，因此不误标长寿命发动机的中段。
- **尺度无关**：每台发动机都得到相同的"生命周期位置"分布。
- 只改损失质量，不复制行、不改特征 schema、预测仍只需要 `inputs`。

实现见 `contest_baselines/strategies.py` 的 `_unit_shortness` 复用。

### 4.3 候选池与配置

`contest_baselines/adapters/profile_c.py`：

- 假设顺序：`the-degradation-is-relative` 提到首位。
- `weight_horizon()` → `None`：**绝对阈值加权彻底停用**。
- `test_horizon()` → 仍返回 200，但**只用于记录切片**，不再进入训练。
- `degradation_alpha()` → `0.5`（12 折实测中全量口径下胜出次数最多的值）。

### 4.4 epoch 预算

`contest_baselines/strategies.py`：`the-degradation-is-relative` 的 base 预算 30 → **65**。

`contest_baselines/adapters/profile_c.py`：`epoch_scale()` 仍为 0.5，
最终 C 的十轮预算为 32 → 75 epoch。

依据见第 5.4 节：40/80 epoch 在留出发动机上分别赢基线 10/12 和 11/12 折，
而 20 epoch 只有 5/12。

`contest_baselines/adapters/base.py`：

- 修复了一处**重复定义**：`test_horizon` / `weight_horizon` / `selection_view` / `selection_guard`
  在同一个类里被定义了两遍，后一份覆盖前一份，导致 `selection_guard` 实际生效值是 0.10
  而不是文档声称的 0.05。已删除重复块，现在 0.05 真正生效。
- 新增 `degradation_alpha()` 默认方法。

## 5. 验证

### 5.1 单元测试

`389 passed, 1 skipped, 135 subtests passed`。

新增/改写的测试：

| 测试 | 验证内容 |
|---|---|
| `SelectionSliceIsEvidenceTest` | 切片不能否决全量改善、不能挽救全量退化；切片仍被记录 |
| `CompareJointTest`（改写） | 新判决规则的全部分支 |
| `test_the_selection_slice_is_evidence_not_the_decision` | `compare` 与 `compare_joint` 对齐 |
| `RelativeDegradationWeightTest` | 权重是**相对**的：120/400/500 循环的发动机得到相同形状的权重曲线 |
| `test_the_weight_does_not_use_an_absolute_threshold` | 相对权重不误标长寿命发动机 |

### 5.2 留出发动机上的端到端对比

`research/tracks/c_verify.py`（12 折）：

| 配方 | 留出均值 | 基线 | 差 | 赢基线 |
|---|---|---|---|---|
| **新 `deg0.5`（相对退化度）** | **55.576** | 55.218 | **+0.358** | **5/12** |
| 旧 `surv150`（绝对阈值） | 56.905 | 55.218 | +1.688 | 3/12 |
| `cap150`（绝对阈值 + 截断） | 64.792 | 55.218 | +9.575 | **0/12** |

新配方直接胜过旧配方 **7/12** 折。

### 5.3 权重强度与"到底什么在起作用"

`research/tracks/c_alpha.py`（12 折 × 8 配方）：

| 配方 | 留出均值 | 差 vs 基线 | 赢基线 |
|---|---|---|---|
| `deg0.5` | 55.576 | +0.358 | 5/12 |
| `deg1.0p0.5` | 55.585 | +0.367 | 6/12 |
| `deg0.25` | 55.604 | +0.386 | 6/12 |
| `deg1.0` | 55.632 | +0.415 | 5/12 |
| **不加权（对照）** | 55.677 | +0.460 | 6/12 |
| `deg2.0` | 55.929 | +0.711 | 5/12 |
| `surv150` | 56.905 | +1.688 | 3/12 |
| `cap150` | 64.792 | +9.575 | 0/12 |

**配对 Wilcoxon 检验**：

- `deg0.5` vs 不加权：p = **0.68**（**统计上不可区分**），7/12 折占优
- `deg0.5` vs `deg1.0p0.5`：p = **0.91**（平局）

这是一个必须诚实写进报告的结论：**相对退化度加权本身与不加权没有统计差异**。
真正的收益来自**不再使用绝对阈值家族**（`cap150` 差 9.6 RMSE，0/12 赢基线）。
`alpha` 的选择因此按"留出均值最低 + 与相邻取值打平"取 0.5，并在文档里如实标注其不显著。

### 5.4 真正的杠杆是 epoch 预算

既然权重不显著，就去找真正能动分数的杠杆。
`research/tracks/c_epochs.py`（12 折，权重固定为 `deg0.5`）：

| epochs | 留出均值 | 基线 | 差 | 赢基线 | 用时 |
|---|---|---|---|---|---|
| 10 | 55.527 | 55.218 | +0.309 | 4/12 | 4.4 s |
| 20 | 55.576 | 55.218 | +0.358 | 5/12 | 8.6 s |
| **40** | **54.594** | 55.218 | **−0.624** | **10/12** | 16.8 s |
| **80** | **54.563** | 55.218 | **−0.655** | **11/12** | 32.5 s |

配对 Wilcoxon 检验：

- **ep80 vs 基线**：p = **0.034**，11/12 折占优
- **ep40 vs 基线**：p = **0.0024**，10/12 折占优
- **ep80 vs ep20**：p = **0.027**，10/12 折占优

**结论：epoch 预算才是 C 方向的主要杠杆。**
曲线不是单调的：10 epoch（55.527）和 20 epoch（55.576）都比基线差，
到 **40 epoch 才越过基线**（54.594，赢 10/12），80 epoch 再好一点点（54.563，赢 11/12）。
现行生产的 C 预算是 `base 30 × epoch_scale 0.5` = **15 epoch**（第 1 轮），
正落在**拐点左侧**——那个区间的留出表现比基线**差** 0.3～0.4 RMSE。

这同时解释了平台那一次跑的表现：平台那 10 轮里，每轮都在换假设，
但**始终没有把预算推到能赢的区间**，而旧切片规则又把最好的候选否掉了。

### 5.5 生产预算的最终取值

`the-degradation-is-relative` 的 base 预算设为 **65**：

- 不加缩放时为 65, 75, ..., 145, 150 —— 十轮**严格递增**，
  符合"重复的假设仍必须是不同的实验"这条规则
  （base 取 70 会在第 9、10 轮撞上 150 上限而重复）。
- C 的 `epoch_scale = 0.5` 把它变成 **32 → 75 epoch**，
  正好覆盖第 5.4 节实测的 40 / 80 拐点区间。
- 全量 113 089 行训练 **80 epoch 实测 40.2 秒**，墙钟安全。

### 5.6 平台隐藏集行数

`y <= 90` = 9 646 行 vs 隐藏集 9 687 行，差 41 行（0.42%）。

## 6. 为什么这次不会再退回

1. **选型口径与隐藏集行数一致**：隐藏集是截断的，我们知道（9 687 行）。
   既然是截断，为什么不能用匹配的截断？——因为第 3 节的实验证明**任何**截断都负相关，
   包括与隐藏集行数最接近的 `y <= 90`（ρ = −0.499，12/12 折选出垫底候选）。
   截断的**位置**不可知，所以截断**不能**用于选型。
2. **不再有隐藏的代理目标**：训练权重的目标现在是可解释的相对退化度，
   不再是一个与真实指标负相关的截断代理。
3. **判决与平台口径一致**：平台报告里显示的就是全量 RMSE，
   判决用同一个数，`reason` 里写的和平台显示的能对上。
