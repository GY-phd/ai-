## 一、项目背景与问题定义

工业模型部署后，设备的工作点、负载、材料批次会持续变化，导致输入分布与
输入-输出关系发生漂移。一次训练、长期有效的静态模型会逐渐"失准"，
产生误报、漏报与质检失准。

赛题要求构建一个工业模型自进化系统:在漂移数据流上自动维持并提升模型性能，
无人工干预地完成"漂移监测 — 诊断归因 — 实验优化 — 评估上线 — 回滚"闭环，
并实现模型层自迭代 + 策略层自改进的两层受控 RSI 机制。

三个方向（数据集）:

| 方向 | 任务 | 指标 | 方向 |
|---|---|---|---|
| A | UCI Gas Drift（多分类） | Macro-F1 | 越高越好 |
| B | 轴承 RUL（回归） | RMSE（分钟） | 越低越好 |
| C | 工业退化序列（回归） | RMSE | 越低越好 |

### 1.1 真正的难点不是"训一个更好的模型"

在公开验证集上刷分是容易的，难点是在隐藏测试流上持续不退化。隐藏测试流与
公开验证集并不完全同分布，因此系统的瓶颈不在模型容量，而在选型口径:系统
每一轮都要在"保留父模型"与"采纳候选"之间做决策，这个决策一旦建立在错误的
度量上，所有后续优化都会朝反方向累积。

本项目最核心的工程成果，正是定位并修复了这一类度量层的根因错误 ——
而且是两处（详见第三节与第四节）。

## 二、总体方案:两层受控自进化架构

### 2.1 架构分层

系统采用严格的分层架构，每一层只做一件事，边界由接口固定:

```
┌──────────────────────────────────────────────────────────────┐
│  View 层        contest_baselines/layers/view/               │
│                 api.py / server.py —— 对外只暴露观测面          │
├──────────────────────────────────────────────────────────────┤
│  Controller 层  contest_baselines/layers/controller/          │
│                 round.py —— 协议的唯一所有者                    │
│                 读父模型→读公开集→定假设→测父→建候选→测候选→   │
│                 判决→落账→问模型→提交→收尾                     │
├──────────────────────────────────────────────────────────────┤
│  Model 层       contest_baselines/layers/model/               │
│                 checkpoint.py / ledger.py / metrics.py / state.py │
├──────────────────────────────────────────────────────────────┤
│  Profile 适配层 contest_baselines/adapters/                   │
│                 profile_a / profile_b / profile_c             │
│                 每方向的假设库、度量口径、选型视图、护栏         │
├──────────────────────────────────────────────────────────────┤
│  Reference      contest_baselines/model.py                    │
│                 平台工件格式与前向传播（平台自带的参考实现）       │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 一轮的固定顺序（不可协商）

```
open_parent → read_public → plan → measure_parent → build_candidate
→ measure_candidate → decide → record → consult_the_model → submit → finish
```

三条顺序上的硬约定，每一条都有代价支撑:

1. 父模型先测:候选永远与父模型的自身读数比较，而不是与某个历史最优比较。
   这让每一轮都是可归因的局部改进，不会因为历史最优不可复现而回退。
2. 判决先于问模型:模型是对已经做出的判决的复核，不是判决的输入。
   否则模型的一次幻觉就会直接改变选型。
3. 落账先于提交:账本、SwanLab 记录、模型回执三者先写盘，再把工件交出去。
   即使提交后崩溃，证据链仍然完整。

### 2.3 受控机制（防止无限制恶意迭代）

赛题明确要求"需具备受控机制，防止无限制的恶意迭代"。系统的四道闸门:

| 闸门 | 作用 |
|---|---|
| 父模型只读 | 通过 `rnd.parent.path` 打开，校验平台声明的摘要，绝不写回 |
| 度量护栏 | 候选必须在主指标上有可接受的回归幅度上限，全量 RMSE 劣化超过 +5% 一律不采纳 |
| 方向一致性 | 分数变好但不是假设预测的方向，判为证伪而非确认，不采纳 |
| 受控预算 | 每方向的 epoch 预算由轮次严格递增、有上限，由策略层而非模型决定 |

模型层的"模型自迭代"体现在:候选是从父模型出发的精确副本（权重、Adam 动量、
epoch 计数、归一化状态全部继承），只有训练过程被假设改变，因此任何一轮的
效果都能精确归因到那一个改动。

## 三、第一处根因:C 方向选型口径的定位与修复

### 3.1 现象

平台实测（v5 镜像）:C 方向隐藏测试 RMSE 56.25329，而静态基线为
52.8686，劣化 +10.06%，直接违反"封闭评测综合性能不低于组委会静态基线"
这一基础门槛。

### 3.2 错误的假设

我们最初假设"隐藏测试协议是早期寿命截断，因此应该用截断切片
（$y \le 90$）来选型"。这个假设看起来很有道理，但从未被验证。

### 3.3 反向工程:隐藏集规模

在公开验证集上统计 $y \le 90$ 的样本数，得到 9 646 条；而平台隐藏测试规模
经反推为 9 687 条，偏差仅 0.4%。这看起来印证了截断假设 —— 但它只说明
规模对得上，完全不能说明度量对得上。

### 3.4 判决性实验:12 折留一轴承交叉验证

我们构造了 12 折"留一引擎（轴承）"的严格交叉验证:在每一折上用一个子集
做选型，用完全没参与选型的另一个子集做真实评测。测试了 7 种截断阈值:

| 截断切片 | 与真实留出集 RMSE 的 Spearman 相关 |
|---|---|
| $y \le 50$ | −0.31 |
| $y \le 75$ | −0.42 |
| $y \le 90$ | −0.47 |
| $y \le 100$ | −0.50 |
| $y \le 120$ | −0.53 |
| $y \le 150$ | −0.53 |
| $y \le 200$ | −0.53 |

所有截断切片与真实泛化能力都是负相关。 按切片选型在 12 折里 12/12
都选中 `cap150`，而它在留出引擎上排名倒数第一（11/11 折，RMSE 73.73 vs
基线 59.87）。而按全量 RMSE 选型，相关性 $\rho = +1.0$，平均排名 1.00，
并且在 7/12 折上优于基线。


### 3.5 机理

绝对阈值（$y \le 90$）把长寿命轴承的中段误判成了寿命末期。一根寿命
3000 分钟的轴承在 $y=90$ 时仍处于健康中期，但在截断切片里它和一根寿命
80 分钟、已经报废的轴承长得一模一样。切片因此丢失了尺度信息，把不同寿命
尺度的引擎混为一谈。

### 3.6 修复

1. 判决口径改为全量 RMSE:截断切片降级为只记录、不裁决。切片仍然被
   测量并写进账本（可审计），但不再有否决权，也不再能挽救回归。
2. 全量护栏:候选若让全量主指标劣化超过 +5%，即使切片变好也不采纳。
3. 相对退化度加权替代绝对阈值加权:权重 $w = 1 + \alpha\,(1 - y/u_{\max})$
   是尺度无关的，任何寿命尺度的引擎都按同一条退化路径对待。经验上
   `deg` 加权与不加权在统计上不可区分（Wilcoxon $p = 0.68$）——
   真正的收益来自剪掉灾难性的绝对阈值。

### 3.7 效果

| 口径 | 留出集排名 | 优于基线的折数 | 与真值的相关性 |
|---|---|---|---|
| 截断切片选型（旧） | 12/12 折倒数第一 | 0 / 12 | −0.47 |
| 全量 RMSE 选型（新） | 平均排名 1.00 | 7 / 12 | +1.0 |

同时发现 epoch 预算不足是另一个被掩盖的瓶颈:15 个 epoch 是欠训练的。
把基础预算从 15 提到 65（C 方向按 0.5 缩放为 32–75）后:

| epoch 预算 | 留出集 RMSE 改善 | 胜出折数 | p 值 |
|---|---|---|---|
| 40 | −0.624 | 10/12 | 0.0024 |
| 80 | −0.655 | 11/12 | 0.034 |

## 四、第二处根因:"最差阶段"底线的修复

### 4.1 现象

客观评分里有一条 5 分的"最差阶段表现"，口径是"漂移流中表现最差阶段的
底线能力"。它量的是部署模型在漂移流各阶段的最差读数 ——
而部署模型只在候选通过闸门时才替换，所以它是整条部署轨迹的性质。

平台 2026-11-25 的正式评测里这条是 0.182 / 5。

### 4.2 定位:把误差拆成"偏移"与"形状"

把 C 的公开验证集按每行在自己发动机寿命中的位置切成五段
（尺度无关:150 循环与 435 循环的发动机各贡献五段等量数据），
再把每段误差拆成"常数偏移"与"形状误差":

| stage | 1（新鲜） | 2 | 3 | 4 | 5（最晚） |
|---|---:|---:|---:|---:|---:|
| 静态基线 RMSE | 78.5433 | 50.0303 | 48.4539 | 47.4816 | 28.1252 |
| 其中偏移占比 | 41.8% | 5.0% | 15.6% | 49.8% | 25.0% |


最差阶段就是新鲜段，而它的误差有 41.8% 是常数偏移 —— 模型系统性地把
剩余寿命预测得偏小。新鲜段的绝对目标最大（一台 435 循环发动机的新鲜快照，
剩余寿命接近 435），偏移的绝对量也最大。

### 4.3 为什么额外训练治不好

新鲜行在训练分布里只占极小份额（435 循环发动机的第一行几乎不可见），
而评分行铺满整个寿命周期。训练目标里新鲜行的权重，结构性地低于评分分布里
新鲜行的权重 —— 这是分布差异，不是拟合不足，再多 epoch 也拉不回来。

三组独立实验都指向同一结论:

| 配方 | 全量 RMSE | 最差阶段 |
|---|---:|---:|
| 静态基线 | 52.8686 | 78.5433 |
| 纯续训，零权重 | 51.0658 | 79.7145 ← 已经变差 |
| 生产权重 `1+0.5·相对退化` | 51.3105 | 81.7126 |
| 阶段均衡权重 | 51.0687 | 79.8160 |

这不是权重形状的问题，是训练本身的问题。 而且注意:纯续训把全量 RMSE
从 52.8686 降到 51.0658，看起来是改进 —— 这个根因在全量指标上几乎看不出来。
底线必须单独拆出来测。

### 4.4 修复:输出层仿射校准

常数偏移是仿射映射最擅长消除的东西。拟合最小二乘映射
$y \sim a \cdot \text{输出} + b$（只在训练行上拟合 —— 验证集是测量集，
在它上面拟合就是泄漏），并把映射折叠进输出层:

```
logits' = a · logits + ((a − 1) · target_mean + b) / target_scale
```

折叠后的模型就是那个 checkpoint —— 平台跑的是它自己的参考前向传播，
看到的就是校准后的模型，不需要任何平台侧的后处理。
折叠精度已验证到 1.7e-13；斜率非正时拒绝应用（那是符号翻转，不是校准）。

留一发动机 6 折验证（模型与校准都只在没见过的发动机上拟合）:

| 读数 | 静态基线 | 原始续训 | 校准后 |
|---|---:|---:|---:|
| 全量 RMSE | 52.8686 | 51.2753 | 51.1769 |
| 最差生命周期阶段 | 78.5433 | 77.7829 | 76.6673 |
| 最差工况 | 63.2368 | 62.7544 | 62.4194 |

三个读数同时改善 —— 不是拿底线换头条，而是两边一起抬。

### 4.5 效果

v10 离线演练的部署轨迹底线:

| 读数 | 静态基线 | v9 底线 | v10 底线 | v10 相对基线 |
|---|---:|---:|---:|---:|
| 全量 RMSE | 52.8686 | 50.4784 | 50.6676 | −2.20% |
| 最差生命周期阶段 | 78.5433 | 75.5446 | 75.6051 | −2.94% |
| 最差工况 FD004 | 63.2368 | 61.8665 | 61.8011 | −1.44% |

第 2 轮就把最差阶段从 80.09 拉回 76.31，一次校准不增加任何 epoch，
离线总代价还下降 1.9%（612.3 s vs 624.0 s）。

## 六、安全性与合规

| 要求 | 落实 |
|---|---|
| 不得植入恶意代码 | 镜像只有一个入口 `/app/harness.py`，代码全部开源可审 |

## 七、结论

本项目交付的不只是一个刷分的训练脚本，而是一套可审计、可归因、可回滚
的工业模型自进化系统:

1. 架构上，用分层 + 固定轮序 + 三重记录，把"受控自改进"落成可检查的代码结构；
2. 方法上，通过 12 折留一交叉验证定位并修复了一个反直觉的度量根因，
   把 C 方向的选型从"12/12 折倒数第一"翻转为"平均排名 1.00"；
3. 方法上（第二处），把误差拆成"偏移"与"形状"后定位到新鲜段的
   41.8% 常数偏移，用折叠进输出层的仿射校准把
   全量 / 最差生命周期阶段 / 最差工况三个读数同时抬高，
   且不增加任何 epoch；
4. 工程上，离线演练 10 轮 × 3 方向全部真实执行，A/B/C 三个方向相对基线
   分别 +2.35% / +32.99% / +4.16%（离线口径），
   三方向的部署底线均高于静态基线，且总代价比上一版更低。

最有价值的经验是:在工业自进化系统里，最危险的不是模型不够强，而是度量
选错了却还在自信地优化。 系统用留出验证、护栏与证伪机制，把这类错误变成
可以被发现和阻止的工程事实，而不是一次看不见的 −10%。

第二重要的经验是:"最差阶段"这类底线指标不会从头条数字的优化里顺带拿到。
本次的根因在全量 RMSE 上几乎看不出来 —— 纯续训让全量 RMSE 从 52.8686 降到
