# 官方数据适配说明

## 1. 适配原则

官方数据包格式在规则中未完全明确（CSV / Parquet 均可能），因此系统采用
**"约定优于配置" + 单点适配** 的设计：

- 所有文件读取都经过 `src/evo/data.py::OfficialAdapter`
- 只要数据里能识别出 **特征列 + 标签列（可选时间戳列）**，无需改代码
- 若命名特殊，仅需改 `configs/default.yaml` 的 3 个字段

## 2. 落地步骤

### 2.1 放置文件

```
data/official/
├── train.csv        # 训练集 (含标签)
├── valid.csv        # 验证集 (含标签)
└── stream.csv       # 可选: 本地自测用的模拟流 (隐藏测试流不公开)
```

若官方给的是 Parquet，把 `configs/default.yaml` 中 `data.train_file` / `data.valid_file`
改为对应文件名即可（适配器按后缀自动选择 reader）。

### 2.2 确认配置

```yaml
data:
  label_col: "label"      # 若官方用 y / target / fault / 故障 等, 适配器会自动识别
  task: "binary"          # binary | regression | multiclass
  feature_cols: []        # 留空 = 自动推断 (除标签列与时间列外的全部列)
```

自动识别的标签列候选：`label, y, target, fault, class, 故障, 标签`
自动识别的时间列候选：`timestamp, time, ts, datetime, date, cycle, 工况`

若数据同时含 **ID 列**（如 `sample_id`、`row_id`），请显式写 `feature_cols`，
否则会被当作特征。这是唯一需要人工确认的地方。

### 2.3 校验

```powershell
$env:PYTHONPATH="src"
.\.venv\Scripts\python -m evo doctor
```

期望看到 `train_exists: true`、`valid_exists: true`、`missing_deps: []`。

### 2.4 运行

```powershell
.\.venv\Scripts\python -m evo run
```

此时 `run` 会走官方数据分支（不再用合成流）。审计日志中会记录
`data_loaded.source = "official"` 与数据指纹，便于复现。

## 3. 隐藏测试流的处理

隐藏测试流由评测平台在离线环境提供，届时有两种接入方式（按评测平台 SDK 决定）：

| 方式 | 接入点 | 说明 |
|---|---|---|
| A. 平台给文件 | `data/official/stream.csv` | 自动被适配器读取，零改动 |
| B. 平台给 SDK 迭代器 | `Harness.run()` 中 `self.stream` | 只需把 SDK 的批次包成 `Dataset`，见下 |

方式 B 的最小适配代码：

```python
from evo.data import Dataset
import numpy as np, pandas as pd

def dataset_from_batch(X, y=None, feature_names=None, name="stream"):
    meta = pd.DataFrame({"timestamp": np.arange(len(X), dtype=float),
                         "batch": np.arange(len(X)) // 500})
    return Dataset(X=np.asarray(X, dtype=float),
                   y=None if y is None else np.asarray(y),
                   meta=meta, name=name,
                   feature_names=feature_names or [f"f{i}" for i in range(X.shape[1])])
```

> 系统内部只依赖 `Dataset` 的 `X / y / has_labels / meta / feature_names`，
> 因此任何数据源只要能产出这个结构，闭环即可直接复用。

## 4. 标签延迟（重要）

真实产线标签会滞后到达。配置：

```yaml
runtime:
  label_delay: 0     # 0 = 标签即时可用; N = 标签滞后 N 条样本
```

- `label_delay > 0` 时，系统只用**已解出标签**的样本训练
- 若当前窗口无标签，`_assemble_training_data` 会退回重放缓冲（不消耗新配额）
- 预测仍在无标签窗口上进行，漂移监测也完全不依赖标签（PSI 是纯输入侧检测）

## 5. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `无法识别标签列` | 列名不在候选列表 | 显式设 `data.label_col` |
| PSI 全是 0 | 特征为常量或类别型被转成 float | 检查 `feature_cols`，类别列需先编码 |
| 训练集缺少时间列 | 无时间戳 | 适配器用行号模拟时间，顺序按文件原始顺序 |
| `train_exists: false` | 路径不对 | 确认 `paths.data_root` 相对项目根目录 |
