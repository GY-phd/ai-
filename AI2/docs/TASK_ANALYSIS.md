## 0. 一句话读懂这道题

**在一条会持续漂移的工业数据流上，让一个模型"自己判断该不该更新、更新什么、花多少代价更新"，并且把每一次判断都记账、可复现、可回滚。**

评分不是"谁的模型最准"，而是 **谁的模型在漂移流上长期保持准确，同时每一点性能提升所消耗的算力/标注/Token 最少**。

所以真正被考察的是三件事：

| 层次 | 本质 | 对应赛题原话 |
|---|---|---|
| 算法层 | 漂移感知的持续学习（Continual Learning） | 漂移监测—诊断归因 |
| 系统层 | 成本受控的自动闭环（Trigger → Update → Gate → Rollback） | 实验优化—评估上线—回滚 |
| 智能体层 | 用 LLM+工具（Harness）做"策略自改进" | 模型层自迭代 + 策略层自改进（受控 RSI） |

## 1. 先把规则里的"隐藏约束"读出来

规则里散落着几条决定生死的硬约束，比正文更值得先读：

1. **必须无人工干预**（门槛①）：镜像启动后全程自动，不能有"等人点一下继续"的环节。
2. **必须优于静态基线**（门槛③）：部署后不再更新的模型是基线，你的系统综合性能**低于**它就出局（等于它则分数≈0，仍难晋级）。
3. **实验记录是门槛**（门槛②）：没按《实验记录规范》在 SwanLab 留痕 → 成绩不进排名。**记录不是加分项，是及格线。**
4. **离线运行**：企业赛在指定设备、统一离线环境跑。**你的镜像不能联网** → 驱动 Harness 的大模型权重必须打包进镜像，任何"调 API"的方案直接失效。
5. **资源三位一体计费**：算力（GPU 时长 / 训练额度）＋ 标注配额 ＋ 大模型 Token。三者都要在系统内部实时记账，最后要能自证"我花了多少、换来多少"。
6. **可重跑**：系统自身原因失败可申请重跑一次，取两次较高分 → 意味着**幂等、可重复、失败可恢复**的系统设计能救一次命。
7. **校赛无 PyTRiO 额度**：校赛阶段不提供算力额度，Harness 部分要么用本地开源小模型自测，要么先用"规则代理 + 接口占位"，把闭环跑通。

**立刻要确认的事（今天）**：报名是否已在官网 bjai-edu.cn 完成（11-07 已截止，未报名需马上找本校教务处 + 赛题答疑群确认补报通道）；数据包与专属评测平台 SDK 是否已拿到（平台原计划 11 月初上线，现在应该已开放）。

## 2. 评分机制拆解：把"单位增益"当成目标函数

### 2.1 客观分（平台自动算）

规则原文：*"主要考察单位增益消耗的算力（GPU 时长或训练额度）、标注配额与大模型 Token"*。

写成人话，平台的客观分大致是：

```
Score ≈ Σ(性能增益) / ( w1·GPU小时 + w2·标注条数 + w3·Token数 )
```

推论（这几条直接决定技术选型）：

- **"多试几次"是负资产**。每次超参搜索、每次全量微调都在分母上加钱。→ 必须做**触发式更新**（漂移确认后才动手），而不是定时更新。
- **"用大模型决策"是双刃剑**。27B 模型每步决策的 Token 都很贵，且离线 CPU 推理慢。→ 用 PyTRiO 微调一个 **4B~8B 的"决策小模型"**，只输出结构化动作（JSON），把大模型成本压到 1/5 以下；27B 只在离线蒸馏阶段当老师用。
- **标注必须"少而准"**。→ 主动学习挑样本（不确定性 + 代表性 + 漂移样本加权），伪标签 + 置信度门控，自监督 TTA 先顶一阵，实在不行再要标签。
- **增益要可度量**。→ 系统内部必须有一个**影子验证集 + 滚动评估器**，每次更新前后能算出 Δ，否则无法证明"这次更新值不值"。

### 2.2 主观分（专家打分，四项）

| 维度 | 评审真正想看什么 | 怎么拿分 |
|---|---|---|
| 方法设计与技术路线 | 你有没有"想清楚为什么这么做" | 给出**决策矩阵**：漂移类型 → 动作 → 成本 → 预期收益，而不是罗列模型 |
| 实验规范与分析深度 | 有没有控制变量、有没有负结果 | 每次 run 有假设、有对照、有失败分析；给出**成本-收益曲线**（增益 vs 花费） |
| 安全可控与工业落地 | 会不会把产线搞崩 | 预算硬闸门、动作白名单、变更幅度限制、影子验证、自动回滚、审计日志 |
| 报告与答辩 | 讲不讲得清 | 一条主线："我们看到漂移 → 我们判断 → 我们花最少的钱修 → 我们证明它没退化" |

**主观分占比很大**（客观分只决定排行榜前 20 的初筛），所以从第一天就要按"能写进报告"的方式做实验，而不是最后补。

## 3. 系统架构：五段闭环 + 两条账本

```
                    ┌──────────────────────── 数据流（隐藏测试流，无人工干预） ───────────────────────┐
                    │  x_t (+ 延迟到达的 y_t)                                                      │
                    ▼                                                                             │
   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────────┐   ┌──────────┐   ┌──────────┐   │
   │ 漂移监测 │──▶│ 诊断归因 │──▶│ 决策规划 │──▶│ 实验/更新执行│──▶│ 影子验证 │──▶│ 上线/回滚│───┘
   │ Detector │   │ Diagnoser│   │  Planner │   │  Trainer     │   │  Gate    │   │ Registry │
   └──────────┘   └──────────┘   └──────────┘   └──────────────┘   └──────────┘   └──────────┘
        │               │              │               │                 │               │
        └───────────────┴──────────────┴───────┬───────┴─────────────────┴───────────────┘
                                               ▼
                        ┌──────────────────────────────────────────────┐
                        │ 账本A：资源账（GPU秒/标注数/Token）           │
                        │ 账本B：实验账（假设-配置-指标-结论，同步 SwanLab）│
                        │ 策略库：规则表 + champion/challenger 版本管理  │
                        └──────────────────────────────────────────────┘
```

**模块职责与最小可实现版本（MVP）**

| 模块 | 输入 | 输出（结构化） | MVP 做法 |
|---|---|---|---|
| Detector | 滑窗特征 + 延迟标签 | `{alarm: bool, score, detector_id}` | PSI/KS（无标签）+ ADWIN（有标签），多检测器投票 + 连续 k 窗确认 |
| Diagnoser | 报警上下文 | `{drift_type, top_features, est_affected_ratio, label_needed, confidence}` | 变化点定位 + 效应量排序 + 规则分类（突变/渐变/周期/概念漂移） |
| Planner | 诊断卡 + 剩余预算 | `{action, params, est_cost, est_gain}` | 决策表 + 小模型打分（PyTRiO 微调），预算不够就降级动作 |
| Trainer | 动作 + 数据 | 新模型/校准参数 + 实际消耗 | 只训 head（最快最省）→ adapter → 小学习率全量微调，逐级升级 |
| Gate | 新旧模型 | `{promote: bool, reason, delta}` | 影子集 + 最近窗口回放，Δ 显著且无退化才放行 |
| Registry | 版本 | 可回滚的模型栈 | 保存最近 N 个版本 + 指标指纹，异常自动回滚 |

**两条账本必须从第一行代码就写**，因为"单位增益"要靠它算，报告要靠它画图，主观分要靠它讲故事。

## 4. 技术选型建议（低算力、CPU 可跑）

### 4.1 漂移检测（便宜且鲁棒）

- **无标签侧（主力）**：特征级 PSI / KS 检验（逐维 + 显著性校正）、PCA 子空间余弦漂移、马氏距离、自编码器重建误差（若有预提取特征，直接上前三个）。
- **有标签侧（延迟到达时）**：滑窗准确率/MAE 的 Page-Hinkley、ADWIN、DDM/EDDM。
- **工程要点**：单检测器误报率高，用 **2/3 投票 + 连续 2 窗确认**；同时把"报警"分成 `warn`（只观察）/ `alarm`（可行动）两级，避免频繁小更新把预算烧光。

### 4.2 归因（这一步是主观分的大头）

不要只报"漂移了"，要报**是哪一类、影响哪几维、占多少样本、要不要标签**。建议输出固定 JSON schema（可直接进报告表格），并保留"误报/漏报"人工复盘记录。区分：

- **协变量漂移** P(x) 变、P(y|x) 不变 → 校准/重加权/微调 head 即可，**不需要大量标注**。
- **概念漂移** P(y|x) 变 → 必须新标注，且要防灾难性遗忘。
- **数据质量漂移**（传感器故障、缺失、量纲错）→ 正确动作是**清洗 + 告警**，不是重训。能识别出这一类，评审会认为你懂工业现场。

### 4.3 更新动作（成本从低到高，按序升级）

1. `do_nothing`（+ 记录观察）
2. 阈值/校准参数调整（Platt、温度缩放、决策阈值按代价敏感重设）——几乎零成本
3. 只重训最后一层 / 线性探针（冻结主干）
4. 测试时适应（BN 统计更新 / Tent 式熵最小化）——无标签，极省
5. 小学习率增量微调 + 正则（EWC / SI）
6. 回放缓冲重训（reservoir sampling，按漂移相似度加权采样）
7. 伪标签自训练（置信度门控 + 类别平衡校验）
8. 全量重训（**最后手段**，成本最高，必须有增益证据才做）

**先跑 2→3→4 的组合，通常能吃掉 70% 的漂移**，全量重训留给真正的概念漂移。

### 4.4 超参数优化（赛题标题里的那半句）

- 用 **Optuna（TPE）+ ASHA/Hyperband 早停**，但**预算写死**（例如总共不超过 N 次 trial、总时长不超过 T）。
- 验证方式必须是**滚动回放**（prequential / rolling-origin），不能用随机 K 折——那是实验室做法，会严重高估。
- 真正值得调的超参只有 6 个：学习率、更新触发阈值、回放比例、正则强度、伪标签阈值、检测器灵敏度。**别调 20 个**，性价比会崩。
- 把"超参"和"决策阈值"分开：前者管学得动，后者管报得准（工业上误报/漏报代价不对称，阈值要按代价矩阵定）。

### 4.5 策略层自改进（受控 RSI，拉开差距的地方）

把它做成 **champion / challenger 的规则进化**，而不是"让 agent 随便改代码"：

```
当前策略 P（决策表/打分器）
   ↓ Agent 读实验账本（历史漂移片段 + 各动作的 Δ 与成本）
   ↓ 提出候选规则（改阈值、加条件、换动作优先级）
   ↓ 在"元验证集"（留出的漂移片段回放）上评估 challenger
   ↓ 显著优于 P 且成本不升 → 晋升；否则丢弃并记录负结果
```

**安全护栏（评审必问）**：预算硬上限（超了就强制 `do_nothing`）、动作白名单、单次变更幅度上限、每次晋升留回滚点、全量审计日志、离线无外网、Agent 输出必须过 schema 校验（防幻觉出非法动作）。

## 5. Harness（智能体）怎么落地才"能不亏钱"

规则允许两条路线：**纯持续微调** 或 **Harness 驱动**。建议 **两者都做，但主推 Harness**（主观分更高），并遵守：

1. **决策点稀疏化**：只在"报警确认后"调用 LLM，其余走规则/缓存；同一诊断卡命中缓存直接复用，省 Token。
2. **输出结构化**：LLM 只输出 JSON（动作 + 参数 + 理由），schema 校验失败就回落到规则，避免幻觉污染系统。
3. **模型选择**：优先用 PyTRiO 微调的 4B~8B 决策模型（SFT 到"看诊断卡 → 出动作"），27B 只做离线蒸馏教师。离线 CPU 推理要量化 + 限制 max_tokens。
4. **工具集（Tools）**：`read_metrics` / `run_probe_train` / `evaluate_shadow` / `query_history` / `promote_or_rollback` / `log_experiment`。每个工具自带预算检查和审计日志。
5. **技能（Skills）**：把"漂移处置 SOP"写成可检索的 Markdown 技能文档，让 Agent 复用而不是每次重新推理——既省 Token 又让行为可解释（这也是"DSPy/技能化 Agent"的标准做法）。
6. **记忆**：实验账本即长期记忆（向量检索 + 结构化过滤），检索"同类型漂移上次怎么处理的、花了多少、效果如何"。

## 6. 工程交付：镜像与离线评测（最容易翻车的地方）

提交物是**系统镜像**，不是代码仓库。清单：

- [ ] 固定入口：如 `docker run ... /workspace/run.sh`，一条命令跑完全流程，退出码 0/非 0 明确
- [ ] 完全离线：权重、依赖、tokenizer 全部内置；启动时**不要**做任何网络探测（超时会拖死评测）
- [ ] 依赖锁版本（`requirements.txt` + 预装 wheel），Python ≥ 3.10
- [ ] 确定性：固定 seed、`torch.use_deterministic_algorithms`、单线程/固定线程数、禁止用 wall-clock 做决策（用流内时间戳）
- [ ] 结果落盘格式严格对齐评测 SDK 文档（字段名、行序、编码、时间戳格式），并本地写一个 mock evaluator 自测
- [ ] 资源自记账：GPU 秒/标注数/Token 数写进 `resources.json`，与平台统计口径一致
- [ ] 超时保护：每阶段有 watchdog，超时前输出已有结果（宁可降级也不要 0 分）
- [ ] 幂等 + 断点续跑：中断后重跑结果一致（对应"可重跑一次"规则）
- [ ] 日志：结构化 JSONL + 人读版 Markdown 摘要，方便答辩演示

## 9. 高频失分点（照着躲）

1. **只做"定时重训"**：成本爆炸，且漂移后响应慢 → 客观分崩。
2. **只报"漂移了"不做归因**：主观分第一项直接低。
3. **没有成本账本**：无法自证性价比，评审只能按"感觉"打分。
4. **镜像联网 / 启动探测网络**：离线评测直接挂。
5. **Gate 只看总指标**：被少数类退化蒙混过关，埋下回滚隐患。
6. **实验记录缺失或"只记成功"**：门槛②不过，直接不进排名。
7. **过度拟合公开集**：隐藏流的漂移剧本不同，泛化崩。
8. **Agent 无护栏**：评审一问"它会不会无限迭代烧钱"就答不上来。
9. **忽略"不低于静态基线"**：为了创新牺牲了基础性能，反而不如不更新。
10. **答辩只讲模型不讲决策**：这道题的题眼是"决策"，不是"模型"。

## 附：术语速查

- **RSI（Recursive Self-Improvement）**：系统用自己的产出改进自己，本题特指"策略层"受控地改进"决策规则"。
- **Harness**：驱动大模型的工具 + 技能 + 记忆 + 护栏的组合，不是"一个 prompt"。
- **Champion / Challenger**：在线的当前策略 vs 候选策略， challenger 必须被证明更优才晋升。
- **Prequential / 滚动回放**：按时间顺序"预测→评估→更新"的评估协议，时间序列任务唯一正确姿势。
- **PSI / KS / ADWIN**：分别用于分布漂移、双样本检验、自适应窗口变化检测。
- **EWC / SI / Replay**：三种抗灾难性遗忘的正则/回放手段。
